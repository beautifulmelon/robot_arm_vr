================================================================================
 A. VR 담당에게서 받아와야 할 것
================================================================================

 A-1. [필수] VR 런타임과 장비
--------------------------------------------------------------------------------
   무엇을      헤드셋 기종, 런타임(OpenXR / SteamVR / Quest SDK 등)
   왜 필요     런타임마다 좌표계 규약이 다릅니다. 로봇은 z-up 인데 VR 쪽은
               y-up 인 경우가 흔합니다. 이걸 모르면 손이 90° 틀어집니다.
   받으면      좌표 변환 행렬을 확정해서 Isaac 쪽에 넘깁니다.

 A-2. [필수] 손 포즈 데이터 형식
--------------------------------------------------------------------------------
   무엇을      - 위치 단위 (m / cm)
               - 자세 표현 (쿼터니언 / 회전행렬 / 오일러, 순서와 규약)
               - 기준 원점이 무엇인지 (헤드셋? 플레이 영역 중심? 캘리브레이션 원점?)
               - 컨트롤러 그립인지 실제 손 추적인지
   왜 필요     이게 IK 목표값의 입력이 됩니다.
   받으면      리타게팅 함수의 입력 규격이 정해집니다.

 A-3. [필수] 손가락 추적 데이터 형식
--------------------------------------------------------------------------------
   무엇을      - 손가락별로 무엇이 나오는지 (관절각? 관절 위치? 굽힘 정도 0~1?)
               - 몇 개 관절인지, 어느 손가락인지
   왜 필요     로봇 손은 4손가락 8서보입니다. 사람 손(5손가락)과 매핑이 필요합니다.
   받으면      사람 손가락 → 서보각 8개 리타게팅을 만듭니다.
   ★ 중요      로봇 손 관절각으로 직접 매핑하면 안 됩니다. 반드시 서보각으로
               가야 합니다. 관절 리밋 사각형의 55% 는 실물에 없는 조합입니다.
               (변환 모듈은 이미 servo_map/ 에 있습니다)

 A-4. [필수] 제어 주기
--------------------------------------------------------------------------------
   무엇을      포즈가 몇 Hz 로 오는지 (보통 72 / 90 / 120 Hz)
   왜 필요     Isaac 물리 스텝과 IK 주기를 맞춰야 합니다.
   받으면      Isaac 쪽 시뮬레이션 dt 와 decimation 을 정합니다.

 A-5. [필수] 작업공간 매핑 방식
--------------------------------------------------------------------------------
   무엇을      사람 팔 움직임을 로봇에 어떻게 옮길 것인지
               - 1:1 로 갈지, 스케일 계수를 곱할지
               - 클러치(버튼 누르는 동안만 추종) 방식을 쓸지
               - 절대 위치인지 상대 변위인지
   왜 필요     로봇 팔 도달거리는 사람 팔보다 짧습니다. 그냥 1:1 로 두면
               사용자가 조금만 팔을 뻗어도 도달 한계에 부딪힙니다.
   받으면      스케일 계수를 확정합니다.

 A-6. [있으면 좋음] 기록 형식
--------------------------------------------------------------------------------
   무엇을      모방학습 데이터를 어떤 형식으로 저장할 계획인지
               (LeRobot dataset? HDF5? 자체 형식?)
   왜 필요     SO-101 때는 관절각만 기록하면 됐는데, VR 은 EE 포즈도
               같이 기록해야 합니다 (아래 B-4).

 A-7. [있으면 좋음] 햅틱/피드백 유무
--------------------------------------------------------------------------------
   무엇을      진동 피드백을 쓸 계획인지, 쓴다면 무엇을 기준으로 할지
   왜 필요     접촉력을 시뮬에서 뽑아 넘겨야 하면 Isaac 쪽 설정이 늘어납니다.


================================================================================
 B. Isaac Sim 담당에게 반드시 알려줘야 할 것
================================================================================

 B-1. [최우선] 이 팔은 5-DOF 라서 6D 포즈를 정확히 못 따라간다
--------------------------------------------------------------------------------
   측정값      리밋 안 임의 자세 500개 전부 6D 자코비안 랭크 = 5 (6 이어야 함)
               위치 3행 랭크 3 / 자세 3행 랭크 3
               -> 위치만, 또는 자세만 보면 다 되는데 동시에는 하나 모자람

   결론        태스크 6개 중 1개를 반드시 포기해야 합니다.

 B-2. [최우선] 포기할 축은 "손바닥 법선축 회전", 손목 롤은 절대 안 됨
--------------------------------------------------------------------------------
   손(hand_base) 프레임에서 태스크 하나씩 빼고 남은 5×5 조건수 (400자세)

       포기할 축              조건수 중앙값    90%      판정
       ----------------------------------------------------------------
       손바닥 법선축 회전 w_x      21.9        318     ★ 권장
       손가락 벌림축 회전 w_y      26.6        731
       손목 롤          w_z     2.5e+10    1.7e+11    ★ 절대 금지

   손목 롤을 포기하면 조건수가 1e10 으로 발산합니다. joint5 가 정확히
   그 축이라, 태스크에서 빼면 joint5 가 할 일이 없어지고 남은 5개 태스크를
   4개 관절로 풀게 됩니다.

   권장 태스크 구성 = 위치 3 + 손목 롤 1 + 손가락 벌림축 회전 1

   ※ 이 축들은 손 프레임 기준입니다. 월드 고정축이 아닙니다.
     가중치 행렬을 매 주기 EE 회전으로 변환해서 적용해야 합니다.

 B-3. [필수] 엔드이펙터 프레임은 hand_mount
--------------------------------------------------------------------------------
       <joint name="hand_mount_joint" type="fixed">
         <parent link="link5"/> <child link="hand_mount"/>
         <origin xyz="0 0 0.18850348" rpy="-1.570796327 0 0"/>
       </joint>

   ★ Merge Fixed Joints 를 켜면 이 프레임이 사라집니다. 꺼야 합니다.

 B-4. [필수] 데이터에 기록할 항목이 늘어난다
--------------------------------------------------------------------------------
       - 팔 관절각 5개 (실제 실행된 값)
       - EE 포즈: IK 목표값과 실제 달성값 **둘 다**
       - 손 서보각 8개
       - IK 잔차 (목표 - 달성)

   이유: 5-DOF 제약 때문에 목표와 달성이 항상 다릅니다. 잔차를 안 남기면
   나중에 "왜 안 따라갔는지" 를 못 찾고, 못 따라간 구간을 학습에서
   걸러낼 수도 없습니다.

 B-5. [필수] 특이점 근처 안전 처리가 새로 필요하다
--------------------------------------------------------------------------------
   SO-101 리더-팔로워는 리더 각도가 항상 유효해서 없던 문제입니다.
   VR 은 도달 불가 목표가 수시로 들어옵니다.
   감쇠 최소자승(DLS) 또는 목표 클램핑을 넣어야 관절이 안 튑니다.
   조건수 90 퍼센타일이 318 이라 자세에 따라 나빠집니다. 감쇠계수를
   고정하지 말고 최소특이값에 따라 조절하는 쪽을 권합니다.

 B-6. [필수] 손은 서보각 액션 유지
--------------------------------------------------------------------------------
   기존 ISAAC_SIM_HANDOFF_SERVO.txt 그대로입니다. 바뀐 것 없습니다.
   VR 로 바뀌면서 오히려 더 잘 맞게 됐습니다.

 B-7. [참고] 나머지는 전부 그대로다
--------------------------------------------------------------------------------
   URDF, 질량·관성, 리밋, effort/velocity, drive gain, 메시 단위 규약,
   mimic/nomimic 구분 — 전부 그대로 유효합니다. 다시 안 만드셔도 됩니다.
   바뀐 건 "팔을 어떻게 명령하는가" 하나뿐입니다.


================================================================================
 C. 아직 우리 쪽에서 못 준 것 (VR 때문에 더 중요해짐)
================================================================================

 C-1. armature (모터 로터 관성)
      DM-J4340P 데이터시트 값을 아직 못 구했습니다.
      VR 텔레옵은 리더-팔로워보다 가감속이 급해서 이 값의 영향이 더 큽니다.

 C-2. 접촉 마찰계수
      파지를 하려면 손가락-물체 마찰계수가 필요합니다. 미정입니다.

 C-3. 팔 관절 damping / friction
      ISAAC_FEEDBACK_v7.txt 에서 요청받은 항목인데 아직 반영 전입니다.

 C-4. 임시 팔 확정본
      실물 조립 방식(3-DOF 안 / 4-DOF 안)이 정해져야 확정본을 드릴 수 있습니다.
      현재 3-DOF 안은 위치 자유도가 2 라서 VR 위치 추종 테스트에 못 씁니다.
