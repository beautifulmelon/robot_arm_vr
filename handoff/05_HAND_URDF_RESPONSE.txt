 3. ★ 가장 중요 — 손은 8-DOF 가 아니라 "서보 8개 / 관절 12개" 입니다 ★
--------------------------------------------------------------------------------
--- 3.1 구조 ---

  요청서 3-3 에서 "8-DOF(손가락 4개 x 2축)" 로 보셨는데, 정확히는 이렇습니다.

      서보    손가락당 2개 x 4 = 8개      ← 실제 액추에이터, 명령 대상
      관절    손가락당 3개 x 4 = 12개     ← URDF 에 들어있는 관절

  AmazingHand 는 손가락마다 서보 2개가 **평행 4절 + 차동 기구**를 통해
  관절 3개(외전 / 근위굴곡 / 원위굴곡)를 움직입니다.

      hand_base ─(외전)→ gimbal ─(굴곡)→ proximal ─(원위)→ distal   × 4

  원래는 닫힌 운동 루프라 URDF 로 표현이 안 되는데, MuJoCo 로 루프를 실제로
  풀어서 등가 직렬 모델로 변환했습니다.
  ★ 이건 근사가 아닙니다 ★ — 손끝 위치를 원본 모델과 비교해 최대 오차 0.0001 mm.
  (요청서 3-3 의 "근사면 근사라고만 적어달라" 에 대한 답입니다)

--- 3.2 ★★ 관절각을 직접 명령하지 마세요 ★★ ---

  서보 2개로 관절 3개가 결정되므로, 관절각을 독립적으로 주면 실물에서
  나올 수 없는 자세가 만들어집니다.

      서보 정사각형 [-90°,+90°]² 를 (외전, 굴곡) 평면에 사상한 결과가
      URDF 관절 리밋 사각형에서 차지하는 비율 = 45.3%

      -> 리밋 안의 조합 중 **55%가 실물에서 불가능**합니다.

  그래서 **명령은 서보각 8개로 하고, 화면 표시용 관절각은 변환해서 쓰세요.**

      VR 트리거/손트래킹 ──(서보각 8개)──┬──> 실물 SCS0009 (그대로 전송)
                                       └──> servo_to_joint_flat() ──> 렌더링

  이렇게 하면 실물과 명령 공간이 완전히 같아지고 도달 불가 자세가 원천적으로
  사라집니다.

--- 3.3 사용법 ---

      import sys; sys.path.append("servo_map")
      from hand_servo_map import servo_to_joint_flat, SERVO_LIMIT_RAD
      import numpy as np

      servo8 = np.radians([-35, 35, -35, 35, -35, 35, -35, 35])   # 편 자세
      q12    = servo_to_joint_flat(servo8)                        # 라디안 12개

  입력 서보각 순서
      [f1_m1, f1_m2, f2_m1, f2_m2, f3_m1, f3_m2, f4_m1, f4_m2]

  출력 관절각 순서 (URDF 조인트 순서와 동일)
      [hand_f1_abduction, hand_f1_flexion, hand_f1_distal,
       hand_f2_abduction, hand_f2_flexion, hand_f2_distal,
       hand_f3_abduction, hand_f3_flexion, hand_f3_distal,
       hand_f4_abduction, hand_f4_flexion, hand_f4_distal]

  단위 전부 라디안. numpy / torch / 스칼라 모두 받습니다.
  정확도: 원본 모델 대비 최대 0.28°  (SCS0009 분해능 0.293°/step 수준)

  역변환도 있습니다 (손트래킹 → 서보각 용):
      from hand_servo_map import joint_to_servo, is_reachable
      t1, t2 = joint_to_servo(A_target, B_target)    # 외전, 굴곡 -> 서보 2개
      ok     = is_reachable(A_target, B_target)      # 도달 가능 판정


 4. 요청서 3장 항목별 회신
--------------------------------------------------------------------------------
--- [3-1] URDF 파일 ---

  손 base 링크 이름 : hand_base
  메시 경로         : 상대경로 (meshes/*.stl), package:// 아님
  관절 이름         : 전부 hand_ 접두어. 정규식 ^hand_f[1-4]_ 로 손 관절만 선택 가능

--- [3-2] ★ 장착 변환 ★ ---

  ★ 커넥터(어댑터)는 URDF 에 **포함되지 않았습니다.** ★
    설계자가 CAD 상에서 어댑터를 만들어 link5 에 붙여두었고, hand_mount 프레임은
    그 어댑터의 장착면에 찍은 것입니다. 즉 어댑터 두께가 이미 반영된 위치입니다.
    어댑터 형상(STL)만 URDF 에 없습니다. 필요하시면 추가할 수 있습니다.

  팔 쪽 (arm/robot_arm.urdf 에 이미 들어있음, 링크 이름은 hand_mount):

      <joint name="hand_mount_joint" type="fixed">
        <parent link="link5"/>  <child link="hand_mount"/>
        <origin xyz="0 0 0.18850348" rpy="-1.570796327 0 0"/>
      </joint>

  hand_mount → hand_base (이 값을 소프트웨어에서 적용하세요):

      xyz = [0, 0, 0]                          어댑터 면과 손 밑면이 맞닿음
      rpy = [1.570796327, -1.570796327, 0]     = (+90°, -90°, 0°)

  ★ 손바닥이 어느 방향을 보는가 (요청서 3-2 의 핵심 질문) ★
    손목 0° 자세에서, base_link 프레임 기준:

        손 +Z (손가락이 뻗는 방향)  →  월드 +Z   (위쪽)
        손 +X (손바닥 법선)         →  월드 +Y
        손 -X (손등)                →  월드 -Y   (카메라가 이쪽을 봄)

    즉 손가락이 위를 향하고, 손바닥은 +Y 를 봅니다.

  검산값 (관절각 0, base_link 프레임 원점 기준):
      hand_mount 높이   533.3 mm
      손끝 높이         622.8 ~ 692.1 mm
      전체 최상단       703.0 mm

--- [3-3] 관절 정보 ---

  URDF 에 limit 이 전부 들어있으니 파싱해서 쓰시면 됩니다. 요약하면:

      관절                 손가락   축의 의미      가동범위
      ------------------------------------------------------------
      hand_fN_abduction    N        벌림/모음      -38.7° ~ +38.2°
      hand_fN_flexion      N        굽힘/폄        -61.7° ~ +44.2°
      hand_fN_distal       N        원위 굽힘      종속 (3.1 참고)

      N = 1,2,3,4     f4 = 엄지

  ★ 이 리밋을 그대로 조작 범위로 쓰지 마세요 ★
    3.2 에서 설명한 대로 리밋 사각형의 55%가 도달 불가입니다.
    리밋은 "안전망"이고, 실제 범위는 서보각 ±90° 가 결정합니다.

  ★ mimic 에 대하여 ★
    hand.urdf (기본)      mimic 없음. 12관절 전부 독립. 서보 매핑으로 계산해 명령.
    hand_mimic.urdf       hand_fN_distal 에 mimic (multiplier 0.9728).
                          8개만 명령하면 원위지골이 따라옵니다.

    서보각으로 제어하실 거면 **기본판(hand.urdf)** 을 쓰세요.
    mimic 판은 원위지골 오차가 최대 5.5° 인데, 서보에서 직접 계산하면 0.32° 입니다.

    ※ mimic 판을 쓰실 경우 12개가 아니라 8개(abduction, flexion)만 명령하면 됩니다.
      단, 파서가 <mimic> 을 지원하는지 확인이 필요합니다.

  손가락 4개는 기구적으로 완전히 동일합니다 (격자 1369점에서 편차 0.0013°).
  손가락별로 다른 것은 관절 축 방향뿐이고 URDF 에 이미 반영돼 있습니다.

  rpy = [+1.5708, 0, -3.14159] 입니다. (요청서의 -1.5708 은 부호가 반대입니다)

  손과의 관계 (base_link 프레임, 관절각 0):

      카메라 위치     (-2.2, -71.7, 514.5) mm
      손 밑면(hand_base)  (0, 0, 533.3) mm
      카메라 → 손 거리    74.1 mm
      카메라 광축과 손 방향의 각도   14.8°

  ★ 물리적 간섭은 없습니다. ★ 카메라는 손보다 18.8 mm 아래, 71.7 mm 옆(-Y)에
  있고, 손은 +Z 로 뻗습니다.

  ※ 카메라가 손등을 정면으로 보도록 설계되어 있습니다
    (손등 법선과 카메라 광축의 내적 = -1.000).
    D435i 가로 반각이 43.5° 이므로 14.8° 는 화면 중앙부입니다.


 7. 요청서 6장 (형식) 확인
--------------------------------------------------------------------------------
  * 단위        m / rad 맞습니다. 단, 메시 STL 은 2장의 scale 주의 참고
  * 좌표 관례   손목축(joint5)이 z 축인 것 맞습니다.
                손도 +Z 가 손가락 방향이라 축 방향은 일치합니다.
                다만 손목→손 사이에 rpy (+90°, -90°, 0°) 회전이 들어갑니다 (3-2)
  * 메시 형식   바이너리 STL 입니다
  * inertial    전부 들어있습니다 (질량/COM/관성텐서). 부하 계산에 쓰세요


 8. 요약 — 체크리스트

  [ ] hand_mount → hand_base 변환 적용
