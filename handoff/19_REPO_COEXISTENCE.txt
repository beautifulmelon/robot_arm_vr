 0. 한 장 요약
--------------------------------------------------------------------------------
  같은 저장소에서 두 갈래가 동시에 돕니다.

      jetson   Quest → Mac → UDP → 젯슨 → CAN → 실물 모터
      isaac    Quest → Mac → UDP → Isaac Sim 브릿지 → 시뮬 로봇

  프로토콜·IK·좌표변환·클러치는 **같은 코드를 씁니다** (그쪽이 그렇게 하신 것,
  옳은 판단입니다). 다른 것은 받는 쪽뿐입니다.

  ★ 그런데 **포트가 완전히 겹쳐 있었습니다.** 둘 다 4443 / UDP 5005·5006·5007 을
    씁니다. 동시에 띄우면 늦게 뜬 쪽이 죽거나, UDP 는 조용히 패킷을 나눠 먹어
    "가끔 명령이 씹힌다" 로 나타납니다. 원인 찾기가 지독합니다.

  → **프로파일(포트 블록)로 분리했습니다.** 아래 §1 만 지키면 됩니다.

      실물   ./run.sh --temp --motors jetson
      Isaac  ./run.sh --temp --motors jetson --profile isaac

    두 줄을 동시에 띄워서 실제로 확인했습니다. §4 에 로그가 있습니다.

 1. 프로파일 — Isaac 쪽은 항상 --profile isaac
================================================================================

  포트는 `src/rpo_teleop/profiles.py` 한 곳에서만 정합니다. 숫자를 코드에
  직접 박지 마세요.

      프로파일   웹(HTTPS)  UDP지령  UDP상태  UDP비컨  Meshcat
      ----------------------------------------------------------
      jetson       4443      5005     5006     5007     7000     ← 실물 (기본)
      isaac        4453      5015     5016     5017     7010     ← Isaac Sim
      test         4523      5085     5086     5087     7080     ← 손으로 돌려볼 때

  쓰는 법

      # Isaac 갈래 텔레옵
      ./run.sh --temp --motors jetson --profile isaac

      # Isaac 갈래 가짜 수신기 (브릿지 없이 Mac 쪽만 볼 때)
      .venv/bin/python scripts/07_fake_jetson.py --profile isaac

      # Isaac 갈래 가짜 송신기 (Mac 없이 브릿지만 볼 때)
      .venv/bin/python scripts/08_fake_mac.py --host <브릿지IP> --profile isaac

  코드에서 쓸 때

      from rpo_teleop import profiles
      pf = profiles.ports("isaac")
      pf.web      # 4453
      pf.cmd      # 5015   Isaac 브릿지가 여기서 지령을 받습니다
      pf.state    # 5016   Isaac 브릿지가 여기로 상태를 되돌립니다
      pf.beacon   # 5017

  ★ **Isaac Sim 브릿지(리눅스 쪽)도 5015/5016 으로 맞춰야 합니다.**
    지금 그쪽 문서에는 5005/5006 으로 적혀 있을 텐데, 그건 실물 젯슨 것입니다.
    브릿지가 5005 를 열면 Mac 에서 실물 갈래를 띄울 때 부딪힙니다.
    (원격이라 당장은 안 부딪히지만, 나중에 젯슨과 Isaac 을 같은 망에 두면
     비컨 브로드캐스트가 섞입니다. 지금 나눠두는 게 쌉니다.)

 2. 무엇이 부딪히는가 — 전수 목록
================================================================================

 2-1. 포트  [해결됨]
--------------------------------------------------------------------------------
    TCP 4443     웹 + WebSocket. Quest 가 붙는 곳.
    UDP 5005     지령 (받는 쪽이 bind)
    UDP 5006     상태 (Mac 이 bind)   ← 여기가 제일 조용히 깨집니다
    UDP 5007     비컨 (Mac 이 bind)
    TCP 7000~    Meshcat (--meshcat 쓸 때만)

  → §1 프로파일로 해결. 시작할 때 미리 검사해서, 막혀 있으면 **누가 물고
    있는지와 조치 방법까지** 찍고 종료합니다. 그냥 예외로 죽지 않습니다.

        ❌ 프로파일 'jetson' 의 포트가 이미 쓰이고 있습니다:
             TCP 4443 (웹/WebSocket)
             UDP 5006 (상태 수신)
           지금 무엇이 물고 있는지 보려면:
             lsof -nP -iTCP:4443 -sTCP:LISTEN

  ※ UDP 검사에 SO_REUSEADDR 을 켜지 않았습니다. 켜면 두 프로세스가 같은
    포트에 바인드되고 패킷이 둘 중 아무데나 가서 절반씩 사라집니다.
    "가끔 씹힌다" 의 정체가 보통 이것입니다.

 2-2. run.sh 가 상대를 죽이던 문제  [해결됨]
--------------------------------------------------------------------------------
  예전 run.sh 는 `pkill -f "scripts/05_teleop_sim.py"` 로 정리했습니다.
  **스크립트 이름으로 죽이므로 다른 프로파일까지 같이 죽습니다.**
  한쪽을 재시작할 때 상대가 말없이 내려가면 원인을 찾기 어렵습니다.

  → 이제 **그 프로파일의 웹 포트를 물고 있는 PID 만** 죽입니다.
    실측: jetson 갈래를 재시작해도 isaac 갈래 pid 가 그대로 살아있음.

 2-3. 인증서 동시 생성  [해결됨]
--------------------------------------------------------------------------------
  두 서버가 같은 `certs/cert.pem`, `certs/key.pem` 을 씁니다. 동시에 뜨면
  한쪽이 **반쯤 쓰인 파일**을 읽어 TLS 가 깨집니다. 증상이 "가끔 인증서 오류"
  라 원인 찾기가 어렵습니다.

  → 락(O_EXCL) + 임시파일 생성 후 `os.replace` 원자적 교체로 고쳤습니다.
    읽는 쪽은 항상 옛 파일 아니면 새 파일을 봅니다. 반쯤은 없습니다.
    스레드 4개 동시 생성 테스트를 붙였습니다 (`test_cert_generation_is_race_safe`).

  ※ 인증서는 **공유해도 됩니다.** SAN 에 이 머신의 사설 IPv4 가 전부 들어가고
    포트는 인증서와 무관합니다. 두 서버가 같은 인증서를 써도 문제없습니다.
    Quest 에서 한 번 "계속 진행" 하면 양쪽 다 통합니다.

 2-4. Quest 세션  [주의 — 코드로 못 막습니다]
--------------------------------------------------------------------------------
  ★ **헤드셋은 한 번에 한 WebXR 세션만 씁니다.**
    두 서버를 동시에 띄워둘 수는 있지만, Quest 에서는 **주소를 골라서**
    한쪽에만 들어갑니다.

        실물   https://<IP>:4443
        Isaac  https://<IP>:4453

    실물 팔을 조종하다가 Isaac 으로 넘어가려면 헤드셋에서 세션을 끊고
    다른 주소로 다시 들어가야 합니다. 이건 구조적 제약이라 못 없앱니다.

  ★ 실물 팔이 붙어 있을 때 Isaac 주소로 잘못 들어가면, 조종은 되는데
    실물이 안 움직입니다(그 반대도). 헷갈리기 쉬우니 **VR HUD 와 대시보드에
    프로파일 이름을 찍도록** 해두는 게 좋겠습니다. 저희 쪽 터미널에는 이미
    찍습니다. 화면 표시는 아직 안 했으니 필요하면 말씀 주세요.

 2-5. 소스 파일  [규약으로 나눕시다 — §3]
