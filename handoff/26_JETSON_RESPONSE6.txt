 3. §7-가 dq — 받되, v_des 로는 안 씁니다
================================================================================

  받는 것은 문제없습니다. 다만 **v_des 에 그대로 넣으면 안 된다**고 봅니다.

 3-1. 이유
--------------------------------------------------------------------------------
  그쪽 dq 는 **안전계층을 통과하기 전의 '의도'** 입니다. 저희 안전계층은 위치를
  제한하고, 그에 따라 실제 지령 속도도 깎입니다.

      velocity_scale 0.3 → 지령 속도 상한 1.131 rad/s
      Mac 이 3.0 rad/s 를 의도했는데 저희가 1.131 로 깎았다면

          kd × (3.0 − 1.131) = 2.0 × 1.869 = **+3.74 N·m**

    실재하지 않는 속도차를 보고 그만큼 더 밀게 됩니다. **속도 제한을 우회하는
    경로가 생깁니다.** 안전계층이 깎은 만큼 kd 가 되밀어주는 셈입니다.

 3-2. 저희 방식
--------------------------------------------------------------------------------
      v_des = (클램프된 지령 − 직전 클램프된 지령) / **공칭 dt**

  · **클램프 후** 값이라 안전계층과 일관됩니다.
  · **벽시계가 아니라 공칭 dt** 로 나눕니다. 안전계층은 매 틱 정확히
    max_step 만큼만 움직이므로 이 값이 정의상 정확하고, 루프 지터가 안 섞입니다.
    (§2-2 에서 "받는 쪽에서 차분하면 지터가 섞인다"고 하셨는데, 저희는 수신
     패킷이 아니라 **자기 지령**을 차분하므로 수신 지터와 무관합니다)

 3-3. 그럼 dq 는 어디에 쓰나
--------------------------------------------------------------------------------
  ★ **의도 신호로는 dq 가 유일합니다.** §4 를 봐주세요 — 마찰 보상 판단에
    저희 클램프된 속도는 쓸 수 없고, 그쪽 dq 는 쓸 수 있습니다.
    그리고 기록 계층에서 "사람이 얼마나 빨리 움직이려 했는가" 를 남기는 데도
    저희 클램프 값보다 그쪽 값이 맞습니다.

  → 보내주십시오. 쓸 데가 있습니다. 다만 v_des 는 아닙니다.


================================================================================
 4. §7-나 마찰 FF "이동 중" 판단 — 지령 속도로도 안 됩니다
================================================================================

  "실제 속도로 판단하면 정지마찰에 걸려 있는 동안 '정지'로 읽혀서 정작 필요한
  순간에 보상이 안 들어간다" — **맞습니다. 저희가 정확히 그 실수를 했습니다.**

  처음에 지령 속도로 방향을 잡았는데 실기에서 전혀 안 먹혔습니다. 원인이
  그쪽 지적보다 한 겹 더 있습니다.

  ★ **정지마찰에 걸리면 저희 클램프된 지령 속도도 0 이 됩니다.**

      정지마찰로 실제가 안 움직임
        → 이격 제한이 지령을 실제 + max_lag 에 **고정**
        → 지령이 더 안 나아감  →  **클램프된 dq = 0**
        → 마찰 보상이 정확히 필요한 순간에 꺼짐

    즉 "지령 기준으로 판단" 도 저희 쪽 클램프 값으로는 같은 함정입니다.
    **이격 제한이 지령 속도까지 0 으로 만들기 때문**입니다.

 4-1. 저희 조치 — 위치 오차로 방향을 잡습니다
--------------------------------------------------------------------------------
      err = 지령 − 실제
      if |err| > 불감대(0.01 rad):  τ_ff = sign(err) × friction_ff

  · 오차는 정지마찰 구간 내내 max_lag 에 붙어 있으므로 **안 꺼집니다.**
  · 불감대는 목표 근처에서 부호가 뒤집히며 진동하는 것을 막습니다.
  · 정지 상태(오차 작음)에서는 안 넣으므로 크리프도 없습니다.

 4-2. ★ 다만 그쪽 dq 를 쓰면 더 나아집니다
--------------------------------------------------------------------------------
  **Mac 의 dq 는 이격 제한과 무관하므로 정지마찰 구간에도 0 이 아닙니다.**
  사람이 손을 계속 움직이고 있으면 의도는 살아 있으니까요.

      "사람이 움직이려 하는가"  →  Mac dq ≠ 0
      "지령이 나아가고 있는가"  →  클램프된 dq (정지마찰이면 0)
      "가야 할 방향"            →  위치 오차 (정지마찰이어도 유지)

  → 지금은 위치 오차만 씁니다. dq 가 들어오면 **"의도가 있을 때만 보상"**
    조건을 추가로 걸 수 있어 더 안전해집니다 (사람이 멈춘 상태에서
    잔여 오차로 보상이 들어가는 것을 막음). 다음 차수에 넣겠습니다.

 6-2. ★ 그런데 더 중요한 것 — τ_ff 가 토크에 전혀 안 나타납니다
--------------------------------------------------------------------------------
      정지 구간:  오차 0.1885 rad,  τ_ff 0.5 N·m 인가 중
      실측 τ   =  -0.03 ~ -0.08 N·m

    이론값은 `kp × 오차 = 100 × 0.1885 = 18.85 N·m` 이고 거기에 τ_ff 0.5 가
    더해져야 합니다. 실측은 **0.05 수준**입니다.

  ★ **직접 토크를 명령했는데 반응이 없다**는 건 스케일 문제 말고는 설명이

    위치 루프를 우회한 경로로도 같은 결과가 나왔습니다.

    → **kp 를 올리거나 FF 를 더 넣어서 풀 문제가 아닙니다.**
      PMAX/VMAX/TMAX/KP_MAX 를 읽어야 합니다. 지금 어댑터 펌웨어

      Damiao 공식 설정 유틸리티나 레지스터 읽기를 지원하는 펌웨어가 필요합니다.
      조달·확인해서 회신드리겠습니다.

 7. 참고 — 이번에 저희 쪽에서 고친 것
================================================================================

  · **피드백 없이 명령하는 것을 막았습니다.**
    CAN 선이 빠진 채로 first_motion 이 전 과정을 그대로 돌았던 적이 있습니다.
    `read_positions()` 가 피드백 실패 시 조용히 마지막 값(초기 0)을 돌려주는데,
    그 상태로 진행하면 **이격 제한이 q_current 로 계산되므로 무력화**됩니다.
    모터가 살아있었다면 팔이 어디 있는지 모르는 채로 계속 밀었을 것입니다.

        · CanBackend.connect() 가 피드백을 확인하고 없으면 거부
        · 제어 루프 중 피드백이 3회 연속 끊기면 즉시 중단

  · 실물 CAN 백엔드는 **캘리브레이션 파일 없이는 못 띄우게** 막았습니다.
    예전엔 파일이 없으면 offset 0 / sign +1 로 조용히 넘어갔는데,
    그러면 첫 명령에 하드스톱까지 갑니다.

  · 브리지 한계를 **URDF ∩ 실측 가동범위**의 교집합으로 씁니다.
    사람이 하드스톱까지 안 밀므로 실측이 더 좁고, 좁은 쪽이 안전합니다.

        joint1  -3.107~+3.107 → **-2.411~+2.384**
        joint2  -1.745~+1.745 → **-1.550~+1.545**
