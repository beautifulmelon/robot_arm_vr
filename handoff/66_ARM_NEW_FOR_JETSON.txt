 0. 한 장 요약

  기구 담당이 신규 5축 팔 + 평행 그리퍼를 보내왔습니다.
  제가 저장소에 등록하고 검증했고, **VR 조종이 됩니다.**

      바로 돌려보기
        ./run.sh --config config/arm_new.json --no-hand

      실물(젯슨)에 붙이기
        ./run.sh --config config/arm_new.json --no-hand \
                 --motors jetson --jetson-host <젯슨주소>

  ★ **--no-hand 가 필수입니다.** 빼면 죽습니다 (§3-3).
  ★ 그리퍼는 아직 안 됩니다. 통로 하나가 필요합니다 → 65번 문서 / §4.
  ★ 실물 붙이기 전에 반드시 §5 (영점·부호·식별자) 를 읽어주세요.
    특히 **joint5 축이 (0,0,-1)** 이고 **식별자 이름**에서 막힙니다.

================================================================================
 3. ★ 제가 넘은 함정 셋 — 실물 쪽도 같은 URDF 를 쓰시니 꼭 보세요
================================================================================

--- 3-1. placo 가 <mimic> 을 무시합니다 ---

  arm_new.urdf 를 그대로 ArmConfig.from_urdf() 에 넣으면 **구동 관절이 9개**로
  잡힙니다. 종속 관절(jaw_l_joint / jaw_r_joint / rocker_r_joint)까지 세기
  때문입니다. 그 상태로 IK 를 돌리면 실물에 없는 자유도를 굴립니다.

      실제 구동   joint1~5 + gripper_joint = 6
      placo 인식  9개

  → scripts/11_make_ik_urdf.py 로 구동 5개만 남기고 나머지를 fixed 로 굳혔습니다.

      .venv/bin/python scripts/11_make_ik_urdf.py \
          --in  assets/arm_new/arm_new.urdf \
          --out assets/arm_new/arm_new_ik.urdf \
          --keep joint1 joint2 joint3 joint4 joint5 --name arm_new_ik

    형상은 그대로 남습니다 (관절만 fixed). 화면에 그리퍼가 계속 보이고
    링크 pose 계산도 정상입니다.

  ※ 손(AmazingHand)을 URDF 에서 떼어내고 서보각으로 따로 몰았던 것과 같은
    처리입니다. 그리퍼도 IK 대상이 아니라 스칼라 하나로 몰면 됩니다.

--- 3-2. EE 프레임이 자동으로 잘못 잡힙니다 ---

  arm_config.py 의 EE_FRAME_CANDIDATES 에 "tool_frame" 이 없습니다.
  그래서 자동 선택이 **camera_mount(손목 카메라)** 를 TCP 로 잡았습니다.
  손끝이 아니라 카메라를 목표로 IK 를 푸는 상태였습니다.

  → --ee-frame tool_frame 을 명시해야 합니다.

      .venv/bin/python scripts/06_setup_urdf.py \
          --urdf assets/arm_new/arm_new_ik.urdf \
          --ee-frame tool_frame --out config/arm_new.json

  ★ 부탁: EE_FRAME_CANDIDATES 에 "tool_frame" 을 넣어주시면 다음 사람이
    안 겪습니다. arm_config.py 는 그쪽 소유라 제가 안 고쳤습니다.

--- 3-3. --no-hand 가 필수입니다 ---

  신규 팔은 그리퍼가 내장이라 **hand_mount 프레임이 없습니다.**
  빼고 실행하면 ArmVisual 이 죽습니다:

      RuntimeError: Frame with name hand_mount not found in model

  서버가 반쯤 뜬 채 죽어서 원인을 알기 어렵습니다. 실제로 겪었습니다.

  ★ 부탁(선택): config 에 손 유무를 적어두면 사람이 안 틀립니다.

      "gripper": "amazing_hand" | "parallel" | null

    또는 hand_mount 프레임이 없으면 자동으로 손을 끄는 것도 방법입니다.


================================================================================
 4. ★ 요청 — 그리퍼 통로 (65번 문서가 본문)
================================================================================

  프로토콜은 **바꿀 게 없습니다.** Command.grasp(0~1)가 이미 있고
  write_positions(q, grasp=, servo=, engaged=) 도 이미 받습니다.

  문제는 05_teleop_sim.py 가 **hand 가 None 이면 grasp 도 None 으로** 보낸다는
  것입니다. 신규 팔은 항상 --no-hand 로 도니까 **그리퍼 값을 보낼 방법이 없습니다.**

      grasp = float(right.trigger)          # 이미 계산돼 있습니다
      if hand is not None:
          hand.set_grasp(grasp)
          servo = grasp_to_servo(grasp)
      else:
          servo = None                      # 그리퍼형 팔: 스칼라만
      motors.write_positions(q, grasp=grasp, servo=servo, engaged=armed)

  받는 쪽 변환은 assets/arm_new/gripper_map.py 가 해줍니다.

      개구(mm)  서보(deg)  gripper_joint(rad)
      ---------------------------------------
        0.5      27.36        -0.2415
       10.0      51.81        -0.0698
       30.0      80.55        +0.2410
       50.0     108.46        +0.5161
       57.9     120.00        +0.6131

  실물 서보는 Feetech STS3215, 유효 구간 10~120°, 개구 0~58mm.


================================================================================
 5. ★★ 실물에 붙이기 전에 — 세 가지
================================================================================

--- 5-1. 영점·부호 표가 필요합니다 (M-12 와 같은 종류) ---

  모터가 Damiao DM-J4340P 로 **완전히 새 하드웨어**입니다.
  URDF 의 joint=0 과 실물 엔코더 0 이 같은 자세가 아닙니다.

      [ ] 관절별 영점 오프셋
      [ ] 관절별 부호 (URDF + 방향 = 모터 + 방향인가)

  UDP 로 오가는 관절각이 **항상 URDF 좌표**가 되도록 젯슨 쪽 변환에 넣어주세요.
  이게 안 맞으면 그 아래 어떤 보정도 의미가 없습니다.

--- 5-2. ★ joint5 축이 (0,0,-1) 입니다. 오타가 아닙니다 ---

  motor5 를 뒤집어 달아서 **출력 플랜지가 link4 에 고정되고 하우징이 돕니다.**
  그래서 모터 정방향 명령이 링크 기준으로는 반대 방향입니다.

  · 부호를 (0,0,1) 로 "고치면" 시뮬에서 롤이 반대로 돕니다
  · 실물 배선 시 **케이블이 j5 와 같이 꼬입니다.** 하우징이 도는 구조라
    모터 커넥터가 회전합니다. ±178° 로 계속 돌리면 케이블이 상합니다.
    → 실사용 리밋을 좁히거나 배선을 확인해 주세요 (64번 §7-(2))

--- 5-3. ★ 팔 식별자 이름에서 막힙니다 — 지금 그대로면 차단됩니다 ---

  check_robot_match 는 config 의 URDF **파일명**을 식별자로 씁니다.
  지금 config/arm_new.json 의 urdf_path 는 arm_new_ik.urdf 입니다.

      받는 쪽이 보내는 robot 값        결과
      ------------------------------------------------
      "arm_new_ik.urdf"               ✅ 통과
      "arm_new.urdf"        ← 자연스러운 이름   ❌ 차단
      "arm_new_nomimic.urdf"          ❌ 차단
      없음 + q 5개                     ✅ 통과 (폴백)
      없음 + q 6개(그리퍼 포함)          ❌ 차단

  ★ M-10 때와 같은 종류의 사고입니다. 그때는 이틀 걸렸습니다.

  둘 중 하나로 정해주세요.

    (A) 젯슨이 robot="arm_new_ik.urdf" 를 보낸다
        — 지금 코드로 바로 됩니다. 다만 내부 파일명이 프로토콜에 새어나옵니다.

    (B) config 에 식별자를 따로 둔다  ★ 이쪽을 권합니다

            "robot_id": "arm_new"

        check_robot_match 가 robot_id 를 우선 보게 하면, 파생 URDF(ik판·
        nomimic판)를 몇 개 만들어도 식별자는 하나로 유지됩니다.
        A-10 의 원래 취지("팔 식별자")에도 맞습니다.

    정해주시면 제 쪽 config 를 맞추겠습니다.

          --config config/arm_new.json --motors 5 --profile test
      .venv/bin/python scripts/08_fake_mac.py \
          --host 127.0.0.1 --profile test --config config/arm_new.json \
          --sweep one-by-one --amp 25

  결과

                        act [-0.0 +34.8 -1.2 +96.7 -172.3]

 7. 홈 자세 — 사용자 요청으로 바꿨습니다
================================================================================

  자동 생성된 홈은 팔이 접혀 되돌아온 자세라, **카메라가 그리퍼 아래**로
  갔습니다. 사용자가 카메라를 그리퍼 위로 올려달라고 해서 바꿨습니다.

      이전  [-28.4  -9.9  +83.5  +42.6  +18.1]   카메라 그리퍼 아래 29.9 mm
      현재  [ -0.0  +34.8   -1.2  +96.7 -158.3]   카메라 그리퍼 위   24.9 mm

  카메라가 link5 축에서 옆으로 35.1mm 벗어나 달려 있어서, 팔의 굽힘 방향과
  손목 롤에 따라 위/아래가 뒤집힙니다.

  현재 홈의 성질
      툴 40.3° 아래 · 카메라 35.8° 아래 · 자코비안 조건수 1.17 (특이점과 멂)

  ★ 64번 §7-(3) 이 경고한 **직립 특이점**(전 관절 0)은 피했습니다.
    단순히 피치 부호만 반전하면 팔이 거의 수직이 되어 그 경고에 걸립니다.

  홈은 A 버튼(홈 복귀)과 IK 시작점에 쓰이므로 조종 감각에 바로 영향이 있습니다.
  바꾸시려면 config/arm_new.json 의 home_q (rad) 를 고치고
  scripts/12_arm_preview.py 를 다시 돌리면 됩니다.
