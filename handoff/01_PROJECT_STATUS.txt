1. 프로젝트 목표
--------------------------------------------------------------------------------
Meta Quest 2 로 5-DOF 로봇 팔을 원격 조종하고, 그 조작 데이터를 모아
LeRobot(HuggingFace) 으로 모방학습(imitation learning)을 시킨다.
팔 끝에는 Amazing Hand(8-DOF 오픈소스 로봇 손)를 붙일 예정.

최종 동작 사슬:

  Quest 2 (WebXR, 90Hz)
    -> 컨트롤러 6-DOF pose + 버튼
    -> 좌표 변환 + 클러치(clutch)
    -> IK (placo)                       [완료]
    -> 안전 계층                         [완료]
    -> 모터 백엔드                       [ ★ 여기가 비어있음 — 인수인계 대상 ]
    -> 실제 모터
    -> lerobot-record -> lerobot-train  [미착수]


2. 완료된 것 (실측 수치 포함)
--------------------------------------------------------------------------------

[2-1] Quest 2 WebXR 입력 — 완료, 실측 검증
  * 갱신 주기 중앙값 90.1 Hz (Quest 2 패널 주사율과 일치), 60Hz 미만 프레임 0.1%
  * 양손 컨트롤러 전체 버튼/축 매핑 실측 확정 (총 9,990 프레임 분석)
      buttons[0] 트리거(아날로그 0~1)   buttons[1] 그립(아날로그 0~1)
      buttons[3] 썸스틱누름              buttons[4] A/X    buttons[5] B/Y
      axes[2]/[3] 썸스틱 X/Y (아날로그)
      * buttons[2], axes[0]/[1] 은 터치패드용이라 Quest 에는 없음(항상 0)
  * 손 트래킹도 양손 감지 확인. 엄지-검지 핀치 거리 3~141 mm
  * 컨트롤러와 손 트래킹은 배타적 — 컨트롤러를 내려놓으면 자동 전환

[2-2] 팔 기구학 — 완료, 실물 URDF 적용됨
  * URDF: assets/robot_arm/robot_arm.urdf (5-DOF, 총 질량 6.716 kg)
  * IK 솔버: placo (LeRobot 표준 스택), 0.027 ms/call
  * 연속 궤적 추종 오차: 중앙값 0.030 mm, p95 0.09 mm, 최대 0.09 mm
  * 관절 한계는 사용자가 실제 가동범위로 좁힌 URDF 적용됨 (2026-08-01):
      joint1 ±178°  joint2 ±100°  joint3 ±178°  joint4 ±120°  joint5 ±178°
  * EE 프레임이 URDF 에 없어서 link5 메시 실측(+0.1885 m z축)해서 추가함
      -> ee_link (IK 목표), hand_mount_link (Amazing Hand 장착점)

[2-3] 안전 계층 — 완료 (src/rpo_teleop/motor_backend.py)
  실기 사고를 막는 방어 장치들. 테스트 30개 통과.
    - 소프트 스타트 (2초 램프)      : 전원 투입 순간 급발진 방지
    - 속도 제한 (URDF의 30%부터)     : 모터가 못 따라가는 급가속 방지
    - 관절 한계 + 마진 (0.05 rad)    : 하드 스톱 충돌 방지
    - 지령-실제 괴리 제한            : 팔이 막혔다 풀릴 때 급발진 방지
    - 워치독 (0.5초)                 : Quest 연결 끊김 시 폭주 방지
    - 트립 후 지령 동결              : 비상정지


3. ★ 비어있는 것 — 인수인계 대상
--------------------------------------------------------------------------------
IK 가 낸 관절각(라디안 5개)을 실제 모터로 내보내는 마지막 구간.

  src/rpo_teleop/motor_backend.py 의 MotorBackend 추상 클래스를 구현하면 된다.
  현재는 MockBackend(가짜, 1차 지연 시뮬)만 있고 실물 백엔드가 없다.

  구현에 필요한 정보 (현재 전부 미확인):
    (a) 모터 제조사/모델      -> CAN 프레임 해석이 달라짐. 틀리면 엉뚱하게 돎
    (b) CAN 인터페이스와 모터 ID
    (c) 관절별 방향 부호      -> 뒤집히면 양의 되먹임으로 한계까지 가속 (위험)
    (d) 관절별 영점 오프셋

  자세한 인터페이스 규격은 02_HARDWARE_INTERFACE.txt 참고.


4. ★★ 확정된 시스템 구성 (2026-08-01 사용자 결정)
--------------------------------------------------------------------------------

  [물리 배치]
    외부(작업 공간) : 로봇 팔 + Mac(macOS, arm64) + Quest 2 + USB-CAN 어댑터
    집              : Linux 데스크톱 (원격 서버)

  [CAN 연결]  -> Mac 에 USB-CAN 어댑터를 직접 연결하기로 결정됨

  ★ 이 결정의 직접적 결과: Roboparty/roboparty_motors 를 쓸 수 없다.

      src/protocol/can/can_iso.hpp:6  ->  #include <linux/can.h>

    Linux SocketCAN 전용이라 macOS 에서 빌드 자체가 안 된다.
    -> python-can 으로 모터 프로토콜을 직접 구현해야 한다.
       상세: 02_HARDWARE_INTERFACE.txt §5

    전제 조건: USB-CAN 어댑터가 slcan(시리얼) 모드를 지원해야 한다.
              지원하지 않는 어댑터(순수 SocketCAN 전용)를 샀다면 macOS 에서 못 쓴다.
              구매 전/후 반드시 확인할 것.

  [원격 제어]  -> 집 Linux 에서 외부의 팔을 실시간 제어하는 것도 시도 예정

    ※ 소프트웨어 담당자가 지연·끊김 위험을 지적했으나 사용자가 진행을 결정함.
      진행하되 아래 구조를 지킬 것:

        집 Linux ──(인터넷, EE 목표 pose만)──> Mac ──(USB-CAN)──> 모터
                                               │
                                               └─ IK + 안전 계층은 Mac 에서 로컬 실행

      * 관절각을 인터넷 너머로 보내지 말 것. EE 목표(6-DOF pose)만 보낸다.
      * IK·안전 계층·모터 루프는 반드시 Mac 로컬에서 돈다.
        네트워크가 끊겨도 Mac 의 워치독(0.5초)이 로컬에서 트립시킨다.
      * 참고 지연: 같은 LAN 1~2 ms / 인터넷 10~50 ms + 지터, 가끔 100 ms 초과
        (제어 주기 예산은 33.3 ms)

  [집 Linux 의 다른 역할]
    * lerobot-train (GPU 학습) — 실시간성 불필요, 지연 무관. 가장 적합한 용도.
    * 데이터셋 보관
    * 원격 개발 환경

7. 알려진 이슈 / 주의사항
--------------------------------------------------------------------------------
 (1) [해결됨] 관절 한계가 실제 가동범위로 좁혀졌다.
     이전에는 전부 ±180° 였는데, 그러면 +179° 와 -179° 가 기구학적으로 같아서
     IK 솔버가 자유롭게 감고 실물 모터에는 "한 프레임에 360° 회전" 명령이 나갔다.
       실측: 속도제한 없으면 한 스텝 최대 변화 360.0° / 추종 p95 311 mm
             속도제한 켜면 2.5° / p95 44.8 mm
     -> placo 속도 제한(enable_velocity_limits)을 켜뒀고, URDF 한계도 좁혀져서
        지금은 ±178° 로 2° 여유가 있다. 그래도 속도 제한은 계속 켜둘 것.
     -> 하드웨어 쪽에서 배선/슬립링 때문에 실제로 더 좁은 관절이 있으면 알려줄 것.

 (2) URDF 를 바꾸면 반드시 06_setup_urdf.py 를 다시 돌려야 한다.
     config/arm.json 이 단일 진실 공급원이고, 관절 한계/작업공간/홈자세/스케일이
     전부 여기서 나온다.

 (3) 모든 관절각이 0 인 자세는 완전 특이점이다.
     joint1(축 0 0 -1), joint3(0 0 -1), joint5(0 0 1) 이 전부 z축이라 나란해진다.
     실측: 자코비안 최소특이값 0.0000, 조건수 5.3e11
     -> 홈 자세를 자동으로 특이점 회피 자세로 고르게 해뒀다 (조건수 1.6)
     -> 실기에서도 all-zeros 를 기본 자세로 쓰면 안 된다.

 (4) placo 가 중립 자세에서 인접 링크 자기충돌 5쌍을 경고한다.
     대개 CAD 여유값 문제지만 실기 운전 전 확인 권장.

 (5) 리치 마진 0.86 을 쓴다. 측정 최대 리치 0.533 m 중 0.459 m 까지만 목표로 허용.
     뻗은 끝은 특이점이라 추종이 무너진다 (실측: 마진 0.97 이면 p95 44.8mm,
     0.86 이면 1.5mm).
     최소 리치도 0.254 m 로 제한한다. 팔이 접히는 안쪽은 특이점·자기충돌 구간이다.

 (6) 홈 자세는 리치 구간 [0.254, 0.459] 의 가운데쯤에서 고른다.
     최대 리치만 기준으로 잡았더니 홈이 최소 리치에 붙어버려, 팔을 안쪽으로 조금만
     당겨도 클램프에 걸렸다 (실측: 홈 리치 0.317 vs 최소 0.254 -> 추종 p95 26 mm).
     현재 홈: q(deg) = [-28.2, +15.3, +24.4, -84.1, +11.6], 조건수 3.05
