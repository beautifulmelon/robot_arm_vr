안녕하세요. 같은 로봇 팔 프로젝트의 소프트웨어 쪽을 맡고 있습니다.
Quest 2 로 5-DOF 팔을 조종해 LeRobot 모방학습 데이터를 모으는 것이 목표입니다.

제 쪽은 "Quest 입력 -> 좌표변환 -> IK -> 안전 계층"까지 완성했고,
그 뒤 "관절각 -> 실제 모터" 구간이 비어 있습니다. 그 부분을 부탁드립니다.


--------------------------------------------------------------------------------
1. 제가 제공하는 것 (이미 동작함)
--------------------------------------------------------------------------------
* 30 Hz 로 관절각 5개(라디안, numpy float64 배열)를 계속 내보냅니다.
* 값은 URDF(assets/robot_arm/robot_arm.urdf) 의 joint1~joint5 부호 기준입니다.
* 이미 안전 계층을 통과한 값이라, 그쪽에서 추가로 제한을 걸 필요는 없습니다.
  - 관절 한계 안쪽(마진 0.05 rad)
  - 속도 제한 적용됨 (URDF velocity 의 10~30%)
  - 기동 2초 소프트 스타트 램프
  - 프레임 간 변화량이 이미 작습니다
* IK 는 0.027 ms 밖에 안 씁니다. 33 ms 예산 대부분이 모터 통신에 쓸 수 있습니다.

3. ★ 확정된 구성과 그 결과
--------------------------------------------------------------------------------
사용자가 결정했습니다: **CAN 어댑터를 팔 옆의 Mac 에 직접 연결**.

  물리 배치
    외부(작업 공간) : 로봇 팔 + Mac(macOS arm64) + Quest 2 + USB-CAN
    집              : Linux 데스크톱 (원격 서버)

  ★ 이 결정의 결과: Roboparty/roboparty_motors 를 쓸 수 없습니다.

      src/protocol/can/can_iso.hpp:6  ->  #include <linux/can.h>

    Linux SocketCAN 전용이라 macOS 에서 빌드가 안 됩니다.
    -> python-can 의 slcan 백엔드로 모터 프로토콜을 직접 구현해야 합니다.

  ★★ 그래서 가장 먼저 확인이 필요한 것:
     USB-CAN 어댑터가 slcan(시리얼 위의 CAN) 모드를 지원하는가?

       지원 O (예): CANable / CANable2, Lawicel 호환, USBtin
       지원 X (예): PEAK PCAN 일부, Kvaser (전용 드라이버 필요, macOS 제한적)

     이미 사셨으면 모델명을, 아직이면 CANable2 계열을 권합니다
     (오픈소스, 저가, slcan 펌웨어 공식 지원).

     확인 방법:
       ls /dev/tty.usb*
       pip install python-can
       python -c "import can; b=can.interface.Bus(interface='slcan', \
                  channel='/dev/tty.usbmodemXXXX', bitrate=1000000); print(next(iter(b)))"

3-2. 원격 제어에 대해 (사용자가 진행을 결정함)
--------------------------------------------------------------------------------
사용자가 집 Linux 에서 외부의 팔을 실시간 제어하는 것도 시도하려 합니다.
제가 지연·끊김 위험을 말씀드렸고 그래도 해보시겠다고 하셨으니, 진행하되
아래 구조는 지켜주셨으면 합니다.

    집 Linux ──(인터넷: EE 목표 pose 만)──> Mac ──(USB-CAN)──> 모터
                                             │
                                             └─ IK + 안전 계층은 Mac 로컬 실행

  * 관절각을 인터넷 너머로 보내지 마세요. EE 목표(6-DOF pose)만 보냅니다.
  * IK·안전 계층·모터 루프는 반드시 Mac 로컬에서 돌아야 합니다.
    그래야 네트워크가 끊겨도 Mac 의 워치독(0.5초)이 로컬에서 트립시킵니다.
  * 참고 지연: 같은 LAN 1~2 ms / 인터넷 10~50 ms + 지터, 가끔 100 ms 초과
    (제어 주기 예산 33.3 ms)
  * 네트워크 구간은 제가 맡겠습니다. 하드웨어 쪽은 Mac 로컬의 CAN 만 봐주시면 됩니다.

4. 제가 모르는 것 — 알려주시면 좋겠습니다
--------------------------------------------------------------------------------
사용자분이 "모터 사양은 하드웨어 담당 쪽에서 안다"고 하셔서 여쭙습니다.

  1. 모터 제조사 / 모델명은 무엇인가요?
     URDF 토크값이 관절별로 40.5 / 31.6 / 25.1 / 20.0 / 20.0 N·m 이고
     속도는 전부 3.14 rad/s 입니다. Damiao DM 시리즈 같은 준직구동 모터로 보이는데
     확실하지 않습니다.
     python-can 으로 직접 구현하려면 그 모델의 CAN 프로토콜 문서가 필요합니다.
     특히 MIT 모드 비트필드의 폭과 스케일(P_MIN/P_MAX, V_MIN/V_MAX, T_MIN/T_MAX)이
     모델마다 달라서, 이 값이 틀리면 각도가 엉뚱하게 해석되어 팔이 예상 밖으로 움직입니다.

  2. USB-CAN 어댑터 모델명은요? (§3 의 slcan 지원 여부가 결정적입니다)
     그리고 각 관절의 모터 ID 는요? (joint1~5)

  3. 감속비가 1:1 인가요? 아니면 모터 회전과 관절 회전 사이에 기어비가 있나요?
     1:1 이 아니면 백엔드에서 환산이 필요합니다.

  4. 비트레이트는 얼마인가요? (1 Mbps?)

자세한 절차는 02_HARDWARE_INTERFACE.txt §6 에 적어뒀습니다. 요점만:

  * 처음에는 velocity_scale=0.1 (URDF 한계의 10%)로 시작해 주세요.

  * 관절 하나씩 ±5° 왕복부터. 절대 처음부터 전체를 움직이지 마세요.

  * 홈 자세로 all-zeros 를 쓰지 마세요.
    joint1(축 0 0 -1), joint3(0 0 -1), joint5(0 0 1) 이 전부 z축이라
    모든 각이 0 이면 세 축이 나란해지는 완전 특이점입니다.
    (실측: 자코비안 최소특이값 0.0000, 조건수 5.3e11)
    config/arm.json 의 "home_q" 에 특이점 회피 자세를 넣어뒀습니다.

6. 제 쪽에서 발견해둔 것 (하드웨어에 영향 있는 것들)
--------------------------------------------------------------------------------
  * [해결됨] 관절 한계가 실제 가동범위로 좁혀졌습니다 (사용자가 URDF 수정).
        joint1 ±178°  joint2 ±100°  joint3 ±178°  joint4 ±120°  joint5 ±178°
    이전에는 전부 ±180° 였는데, 그러면 +179° 와 -179° 가 기구학적으로 같아서
    IK 가 자유롭게 감고 실물 모터에는 "한 프레임에 360° 회전" 명령이 나갔습니다.
    (실측: 속도제한 없으면 한 스텝 최대 변화 360.0°, 추종 p95 311 mm)
    -> placo 속도 제한을 켜둔 상태이고 URDF 도 좁혀져서 지금은 안정적입니다.
    -> 다만 배선/슬립링 때문에 실제로 더 좁은 관절이 있으면 꼭 알려주세요.

  * 리치 0.459 m 까지만 목표로 허용하고 있습니다 (측정 최대 0.533 m 의 86%).
    뻗은 끝은 특이점이라 추종이 무너집니다.

  * 팔 끝 EE 프레임이 URDF 에 없어서 link5 메시를 실측해 +0.1885 m(z) 지점에
    ee_link / hand_mount_link 를 추가했습니다.
    나중에 Amazing Hand(8-DOF, Feetech SCS0009 서보 8개, 약 0.4 kg)를 붙일 예정인데,
    손목 끝에 0.4 kg 이 걸리면 joint5(τ=20 N·m) 부하를 다시 봐야 할 수 있습니다.

  * placo 가 중립 자세에서 인접 링크 자기충돌 5쌍을 경고합니다.
    (base_link-link1, link1-link2, link2-link3, link3-link4, link4-link5)
    CAD 여유값 문제일 가능성이 높지만 실기 운전 전에 확인 부탁드립니다.
