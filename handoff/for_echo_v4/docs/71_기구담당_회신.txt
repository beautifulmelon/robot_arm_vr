 1. ★★ joint1 영점 — joint1 으로는 카메라를 못 올립니다
================================================================================

--- 1.1 먼저 결론 ---

  **joint1 을 아무리 돌려도 카메라의 위/아래는 바뀌지 않습니다.**
  팔 전체가 통째로 도니까 카메라와 툴의 상대 관계가 그대로이기 때문입니다.

  v2 URDF 로 직접 재봤습니다. 툴을 연직에서 45° 기울인 자세에서,
  카메라가 툴축 기준으로 위/아래 어느 쪽에 있는지:

      j1      j5      카메라의 툴축 수직오프셋 z      판정
      ------------------------------------------------------
        0°      0°            -24.82 mm            아래
      180°      0°            -24.82 mm            아래   ← j1 은 무영향
        0°    180°            +24.82 mm            위     ← j5 가 바꾼다
      180°    180°            +24.82 mm            위

  30° / 60° 기울기에서도 같습니다 (각각 ∓17.55 / ∓30.40 mm).

  그리고 **연직 하향 파지 자세에서는 카메라가 항상 TCP 보다 90.56 mm 위**입니다.
  j1 이든 j5 든 무관합니다. 툴축이 연직이면 카메라 오프셋이 수평이 되니까요.

      j1=0    TCP (356.58, 0.00, -104.69)  카메라 (321.48, 0.01, -14.13)
      j1=180  TCP (-356.58, 0.00, -104.69) 카메라 (-321.48,-0.01, -14.13)
      → 두 경우 모두 카메라가 TCP 보다 +90.56 mm 높고, 35 mm 만큼 베이스 쪽입니다.

  즉 joint1 = -178° 로 가신 것은 카메라 때문이 아니라 **다른 이유**입니다.
  아마 §1.4 의 joint2 부호 문제로 보입니다.

--- 1.2 그래서 근본 해결은 이렇게 하면 됩니다 (부품 0개) ---

  j5 가 카메라 면을 바꾸지만, j5 = 180° 는 리밋(±178°) 끝이라 같은 문제입니다.
  그러니 **j5 = 0 에서 카메라가 위로 오도록 조립을 바꾸면** 끝납니다.

      ★ 그리퍼를 motor5 장착면에서 180° 돌려 체결한다.

      · motor5 뒷면(그리퍼가 붙는 면)  M2.5 × 4, 90° 간격 → 180° = 2홀
      · 출력 플랜지(반대 방식일 경우)   M3 × 6, 60° 간격 → 180° = 3홀
        둘 다 180° 가 볼트 홀에 **정확히** 떨어집니다. 새 부품이 필요 없습니다.

      결과
        j5 = 0  →  카메라 위
        j1 = 0  →  팔 정면
        전부 기계 중립. 영점을 손대는 일 자체가 없어집니다.

  귀하의 (A) 안(카메라를 -x 로 이설)과 결과가 같은데, 브래킷을 새로 그리지
  않아도 됩니다. (B) 안(joint1 영점 180° 이동)은 위 §1.1 대로 카메라 문제를
  해결하지 못하므로 권하지 않습니다.

--- 1.3 임시 조치는 되돌려 주시기 바랍니다 ---

  joint1 origin rpy 를 [0 0 π] 로 바꾸신 것은 형상을 안 바꾸는 건 맞습니다.
  다만 **카메라 문제를 해결하지 못하면서 관절값 규약만 바꿉니다.**
  실물 캘리브레이션·로그·문서가 전부 그 규약을 따라가야 하는데, 나중에
  §1.2 로 조립을 고치면 또 되돌려야 합니다.

  ★ 질문에 답: **joint1 을 중립에서 180° 돌아간 자리에서 상시 운용해도 됩니다.**
    motor1 은 하우징이 base_link 에 고정돼 있고 출력 플랜지가 link1 을 돌립니다.
    케이블은 고정된 하우징 쪽에 있어 **꼬이지 않습니다.** j5 와는 다릅니다.
    (j5 는 하우징이 도는 구조라 꼬입니다 — 67 §7-2 경고 그대로입니다.)
    하드스톱은 CAD 상 없습니다.
    그러니 급하면 그대로 쓰셔도 되지만, 필요가 없습니다.

--- 1.4 ★ 확인 부탁 — joint2 부호 ---

  "툴 방위 = joint1 + 180" 이라고 쓰셨는데, 제 URDF 에서는

      joint1 = 0, joint2 > 0  →  팔이 +x(로버 정면)로 뻗습니다
      joint1 = 0, joint2 < 0  →  팔이 -x(뒤)로 뻗습니다

  joint2 축이 (0,1,0) 이고 오른손 법칙이므로 +회전이 +z 를 +x 쪽으로 눕힙니다.
  IK 가 joint2 음수 해를 고르고 있다면 joint1 = 180° 가 필요해집니다.
  **IK 의 분지 선택을 joint2 > 0 쪽으로 잡아 보시겠습니까?**
  그러면 joint1 = 0 에서 정면 작업이 됩니다.

--- 6.1 ✅ D435i 의 camera_mount 는 어느 센서인가 ---

  **어느 센서의 광학중심도 아닙니다. 모듈 뒷면(장착면)의 중앙입니다.**

  CAD 를 열어 재봤습니다 (카메라 컴포넌트 로컬 좌표):

      하우징 Body7   x[-45.37, 45.37] y[-12.37, 12.37] z[-0.10, 24.00]
      → 원점은 x·y 중앙, z 는 **뒷면**. 앞면이 z = +24.

      렌즈로 보이는 형상   z = +20 ~ +22 (앞면 근처)
          x = -32.96 (Ø4 작은 것)
          x = -10.96 (Ø8)
          x = +17.96 (Ø8)

  즉 **광학중심은 camera_mount 에서 축방향으로 약 21 mm 앞, 그리고 옆으로
  11~33 mm 떨어져 있습니다.** 무시할 수 없는 크기입니다. 지적이 맞았습니다.

  다만 이 CAD 는 단순화 모델이라 **어느 것이 RGB 인지 단정할 수 없습니다.**
  (실제 D435i 는 좌IR-프로젝터-RGB-우IR 순이고 IR 베이스라인이 50 mm 인데,
   위 간격은 22.0 / 28.9 mm 로 실물과 다릅니다.)

      ★ 권고 — CAD 를 믿지 마시고 실물에서 뽑으십시오.

        camera_rgb_optical_frame 을 fixed 로 하나 더 다는 것을 권합니다.
        제가 프레임만 파 놓을까요? 값만 주시면 넣겠습니다.

  (1) ★ IK 가 joint2 양수 해를 고르게 할 수 있습니까? (§1.4)

      제 쪽 문서에 반영할 수 있습니다.

  (3) ★ 그리퍼 명령 단위가 무엇입니까 — 개구(mm) 인가요, 서보각인가요?

      그쪽을 1급 인터페이스로 두고 문서를 정리하겠습니다.

  (4) ★ mimic 판과 nomimic 판 중 어느 것을 쓰고 계십니까?
      §3.4 대로 개구 60 mm 를 넘기면 mimic 판은 못 씁니다.

  (5) j5(툴 롤)를 실제로 얼마나 쓰십니까?
      하우징이 도는 구조라 케이블이 꼬입니다. ±90° 안에서 쓰신다면
      리밋을 줄여 두는 편이 안전합니다.

  (6) Isaac 쪽 **충돌 포함** 도달범위 결과가 나오면 공유해 주십시오.
      §4 의 428 mm 는 상한이라 실제로는 더 낮을 수 있고, 그러면 쓰레기통
      개구부를 더 내려야 합니다.

  (7) 쓰레기통 개구부를 본체 **정면**과 **측면** 중 어디에 두는 게
