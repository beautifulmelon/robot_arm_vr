--- 2.1 무엇이 바뀌었나 (scripts/05_teleop_sim.py) ---

      이전   grasp=None if hand is None else float(grasp)
      지금   grasp=float(grasp)

  신규 팔은 그리퍼가 내장이라 항상 --no-hand 로 도는데, 그러면 그리퍼를 몰 값이
  Command 에 **아예 안 실렸습니다.** 이제 항상 실립니다.

  ★ servo(8개)는 AmazingHand 전용이라 손이 있을 때만 채웁니다. 그대로입니다.
  ★ Command 스키마는 안 바뀝니다. grasp 는 원래 있던 필드입니다.

--- 2.2 받는 쪽에서 하실 일 — 이것 하나입니다 ---

      import gripper_map as gm                  # assets/arm_v2/gripper_map.py
      opening = 57.9 + (0.5 - 57.9) * clip(grasp, 0.0, 1.0)
      servo   = gm.servo_for_opening(opening)   # 유효 10~120°

  변환식은 기구 담당의 실측 56점 피팅입니다 (피팅 최대오차 개구 0.04 mm).
  67 §4-4 에 같은 내용이 있습니다.

--- 2.3 값 대응 (Mac 에서 실측 확인) ---

 3. ★★★ joint1 영점을 180° 옮겼습니다 — 실물도 같이 바꿔야 합니다
================================================================================

  ★★★ **이것만은 꼭 읽어주세요. 안 맞추면 첫 지령에 팔이 반 바퀴 돕니다.**

      URDF   joint1 origin rpy  [0 0 0] → [0 0 π]
      관절값  q1_new = q1_old − 180°  (mod 360)

  실물에서 하실 일 — 둘 중 하나입니다.
      (A) joint1 서보의 기계 영점을 180° 옮긴다
      (B) 드라이버에서 지령과 피드백 양쪽에 −180° 오프셋을 건다

  ★ 형상은 하나도 안 바뀌었습니다. 관절값을 읽는 기준만 바뀝니다.
    같은 물리 자세를 옛 모델은 -172°, 새 모델은 +0° 라고 부릅니다.
    tool_frame·camera_mount·link5·조 의 world pose 를 대조했습니다 —
    **위치차 0.0000 mm / 자세차 0.0000°.**

--- 3.0 왜 옮겼나 ---

  홈의 joint1 이 -172° 라 리밋(±178)까지 6° 밖에 안 남았습니다. 더 나쁜 것은
  **못 쓰는 4° 구간이 팔이 정면(툴 방위 0°)을 향하는 자리**였다는 점입니다.
  작업 방향 한복판이 막혀 있었습니다.

      전   joint1 -178~+178 (홈 -172)    좌/우 여유    6° / 350°   막힌 곳 = 정면
      후   joint1 -178~+178 (홈   +0)    좌/우 여유  178° / 178°   막힌 곳 = 뒤(차체)

  뒤쪽은 어차피 차체와 부딪히는 자리라 잃을 것이 없습니다.
  새 규약에서는 **툴 방위 = joint1** 이라 읽기도 쉬워집니다.

--- 3.1 새 홈 자세 ---

      home_q = [   +0.00  +54.51  -84.45  -80.78  +4.90 ]°

  사용자가 VR 로 직접 잡은 자세입니다. 원래 값은 옛 규약의 -178.00° 였는데
  리밋에 정확히 붙어 있어 -172° 로 뺐고, 이번 영점 이동으로 0.00° 가 됐습니다.

      -178° 는 리밋(±178)에 **정확히 붙어 있습니다.**
      안전계층 limit_margin = 0.05 rad = 2.9° 가 이걸 -175.1° 로 당깁니다.
      → 실물 기동 순간 2.9° 점프합니다.

  **툴 높이·툴 각도·카메라 위치는 그대로**입니다. 툴 방위가 +2° → **0°(정확히 정면)** 이 됩니다.

  ★ 첫 통전 때 팔이 홈으로 **스스로 크게 움직입니다.** 주변을 비우고
    비상 정지를 손에 쥐고 시작하세요.
  ★ 위 영점 오프셋을 먼저 맞추고 나서 홈 복귀를 누르세요.

--- 3.2 왜 팔이 반 바퀴 돌아가 있나 (배경) ---

  사용자가 "카메라가 그리퍼 **위**에 오게" 요청했는데, 카메라가 link5 의
  (35.10, 0.01, 142.45) — **+x 쪽**에 달려 있습니다. 그래서 카메라를 위로
  올리려면 팔을 베이스에서 반 바퀴 돌리는 수밖에 없습니다.

  ★ 이번 영점 이동으로 **좌우 여유 문제는 해결됐습니다** (6° → 178°/178°).
    다만 팔이 물리적으로 반 바퀴 돌아 있는 상태로 일하는 것은 그대로입니다.
    카메라를 브래킷 반대편(-x)으로 옮기면 그것까지 없어집니다.
    기구 담당에게는 **CAD 에서 아예 이 영점으로 바꿔 달라**고 요청하겠습니다.
