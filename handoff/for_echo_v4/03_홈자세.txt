 2. 어떻게 정했나
--------------------------------------------------------------------------------
   사용자가 **VR 로 직접 팔을 잡고** 원하는 자세를 만든 뒤,
   scripts/13_pose_snapshot.py 로 그 순간의 관절각을 찍었습니다.

       python3 scripts/13_pose_snapshot.py --write config/arm_v2.json

   계산으로 고른 자세가 아니라 **사람이 조종해 보고 고른 자세**입니다.


 3. ★★★ joint1 영점을 180° 옮겼습니다 — 실물도 같이 바꿔야 합니다
--------------------------------------------------------------------------------
   ★★★ **안 맞추면 첫 지령에 팔이 반 바퀴 돕니다.**

       URDF   joint1 origin rpy  [0 0 0] → [0 0 π]
       관절값  q1_new = q1_old − 180°  (mod 360)

   실물에서 할 일은 둘 중 하나입니다.
       (A) joint1 서보의 기계 영점을 180° 옮긴다
       (B) 드라이버에서 지령과 피드백 양쪽에 −180° 오프셋을 건다

   왜 옮겼나

   사용자가 VR 로 잡은 자세는 옛 규약으로 joint1 = -178.00° 였습니다. 그런데
   리밋이 ±178° 라 정확히 붙어 있었고, 안전계층 limit_margin(0.05 rad = 2.9°)이
   -175.1° 로 당겨 **기동 순간 점프**했습니다. 먼저 -172° 로 뺐지만 그래도
   리밋까지 6° 뿐이었습니다.

   더 나쁜 것은 **못 쓰는 4° 구간이 팔이 정면(툴 방위 0°)을 향하는 자리**에
   있었다는 점입니다. 작업 방향 한복판이 막혀 있었습니다.

       전   joint1 -178~+178 (홈 -172)   좌/우 여유    6° / 350°   막힌 곳 = 정면
       후   joint1 -178~+178 (홈   +8)   좌/우 여유  186° / 170°   막힌 곳 = 뒤(차체)

   뒤쪽은 어차피 차체와 부딪히는 자리라 잃을 것이 없습니다.
   새 규약에서는 **툴 방위 = joint1** 이라 읽기도 쉬워집니다.

   검증 — 형상이 정말 그대로인가

   arm_v1 · arm_v2 모두 홈에서 tool_frame · camera_mount · link5 · jaw_l/r 의
   world pose 를 옛 모델과 대조했습니다.
       **위치차 0.0000 mm / 자세차 0.0000°**
   도달 반경(0.2~472.0 mm)과 최대 높이(428.1 mm)도 그대로입니다.

   다시 적용하는 법 (기구 담당이 새 URDF 를 주면 그 파일은 옛 영점입니다)

       python3 scripts/16_rotate_joint_zero.py --joint joint1 --deg 180 \
           --urdf assets/arm_vN/arm_vN.urdf assets/arm_vN/arm_vN_nomimic.urdf
       python3 scripts/11_make_ik_urdf.py ...   # IK 판 재생성
       python3 scripts/12_arm_preview.py        # arms.json


 4. ★ 왜 joint1 이 리밋 근처로 갈 수밖에 없나 (구조적 문제)
--------------------------------------------------------------------------------
   사용자 요구는 "카메라가 그리퍼 **위**에 오게" 였습니다.
   그런데 카메라가 link5 의 **(35.10, 0.01, 142.45) — +x 쪽**에 달려 있습니다.

   그래서 카메라를 위로 올리려면
       joint5 를 ±110° 이상 돌리거나  (손목 롤 가동범위를 다 씁니다)
       joint1 을 ±178° 근처로 돌리거나  ← 지금 이것
   둘 중 하나입니다.

   ★ 영점을 180° 옮겨 **좌우 여유 문제는 해결됐습니다** (6° → 186°/170°).
     다만 팔이 물리적으로 반 바퀴 돌아 있는 상태로 일하는 것은 그대로입니다.
     카메라를 브래킷 반대편(-x)으로 옮기면 그것까지 없어집니다.
     기구 담당에게는 CAD 에서 아예 이 영점으로 바꿔 달라고 요청할 예정입니다.


 5. 다른 자세를 홈으로 쓰고 싶다면
--------------------------------------------------------------------------------
   1) 서버를 띄우고 VR 로 원하는 자세를 만든다
   2) python3 scripts/13_pose_snapshot.py            # 화면에서 먼저 확인
   3) python3 scripts/13_pose_snapshot.py --write config/arm_v2.json
   4) python3 scripts/12_arm_preview.py              # ★ arms.json 재생성
   5) 서버 재시작

   ★ 4번을 빠뜨리면 대시보드 미리보기가 옛 자세로 남습니다.

   확인할 것
       [ ] 모든 관절이 리밋에서 3° 이상 떨어져 있는가  (안전계층 2.9°)
       [ ] joint1 이 새 규약 값인가 — 옛 값에서 180° 를 뺀 것
       [ ] 영점(직립) 근처가 아닌가 — 5축 Z-…-Z 구조는 툴 축이 베이스 요축과
           일직선이 되면 j1 과 j5 가 같은 일을 해서 랭크가 무너집니다
           (docs/67 §7-(3))
       [ ] 손목 롤 가동범위가 충분히 남아 있는가
           — 예전에 joint5 가 리밋 근처인 자세를 골랐다가 롤이 -20°/+336°
             로 치우친 적이 있습니다
       [ ] 카메라가 그리퍼 위에 있는가
