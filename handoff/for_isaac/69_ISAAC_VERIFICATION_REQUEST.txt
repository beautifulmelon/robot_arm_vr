 0. 왜 지금인가
--------------------------------------------------------------------------------
  사용자가 **실물 ACT 모방학습**으로 가기로 정했습니다. 그러면 시뮬이 필요
  없어 보이지만 그렇지 않습니다. **아직 브래킷도 쓰레기통도 안 만들었습니다.**

      수정 비용은 단계마다 대략 10배씩 오릅니다.
      CAD 1 · 시뮬 1 · 시제품 10 · 조립 후 100 · 현장 1000

  아래 다섯 가지는 **조립 전에만 값이 있거나**, 실물을 기다리는 시간을
  그대로 진도로 바꿔주는 것들입니다. 급한 순서로 적었습니다.

      V-1  카메라 기울기 + 시야 픽셀 검증      ★★★ 브래킷 만들기 전
      V-2  충돌 — 자기 · 본체                 ★★★ 기하학만으로는 못 잡음
      V-3  집기→넣기 전체 궤적이 존재하는가    ★★  쓰레기통 위치 확정용
      V-4  기록 파이프라인 리허설             ★★  실물 대기시간 활용
      V-5  텔레옵 인간공학                    ★   데이터 품질이 곧 정책 품질

  ★ 반대로 **지금 하면 낭비인 것**도 적어뒀습니다 (§8). 마찰이 없는 상태에서
    파지 성공률 숫자를 뽑는 일 같은 것입니다.

 2. V-1  카메라 기울기 + 시야 픽셀 검증        ★★★ 최우선
================================================================================

  브래킷을 만들기 전에 각도를 확정해야 합니다. **URDF 값이 곧 "실물을 이렇게
  달아야 한다"는 규격**이 됩니다.

--- 2.1 ★ 커버리지를 신규 팔 기준으로 다시 냈습니다 ---

  61번의 커버리지 표는 **옛날 팔** 작업영역 기준이라 폐기해 주세요.
  신규 팔은 바닥 도달 범위가 달라서 숫자가 꽤 바뀝니다.

      기울기   보이는 비율   광축이 바닥에 닿는 거리(본체 앞)
      ------------------------------------------------------
        0°        0.0 %      ∞ — 영원히 안 닿음
       30°       29.8 %       +1309 mm
       40°       65.4 %        +890 mm
       45°       73.5 %        +742 mm
       50°       80.7 %        +617 mm
       55°       87.4 %        +510 mm
       60°       92.9 %        +414 mm     ← 권고
       65°       95.1 %        +328 mm
       70°       82.0 %        +249 mm     ← 너무 가까워 다시 나빠짐

      표본 28,069점. 신규 팔 바닥 작업영역(장착점 반경 472mm)에서
      본체 겹침(x -367~+382 · y ±243)을 뺀 영역. 물체 중심 z=35mm.

  ★ 제 권고는 **60°** 입니다. 92.9% 를 덮으면서 광축이 본체 앞 414mm 바닥에
    닿아 작업영역 한가운데를 봅니다. 65° 는 +2.2%p 를 위해 접근 궤적의
    위쪽 여유를 잃습니다.

  ★ **최종 결정은 렌더를 보고 사용자가 합니다.** 50 / 55 / 60 / 65 네 각도로
    같은 장면을 렌더해 주시면 그걸로 정하겠습니다. 예전 렌더에서는 각도가
    커지면 본체가 화면을 크게 차지하는 문제가 있었습니다.

--- 2.2 카메라 파라미터 (62번 그대로) ---

    본체 정면 — Logitech C920      프레임 body_camera_mount
        focal_length 24.0 · horizontal_aperture 33.8603 · vertical_aperture 19.0530
        → HFOV 70.40° · VFOV 43.30°   해상도 1280×720 (★ 반드시 16:9)

    손목 — RealSense D435i **RGB**   프레임 camera_mount
        focal_length 24.0 · horizontal_aperture 32.9895 · vertical_aperture 18.4255
        → HFOV 69.00° · VFOV 42.00°   해상도 1280×720

    ★★ D435i 를 87° 로 넣지 마세요. 87° 는 depth 이고 RGB 는 69° 입니다.
    ★ 두 프레임 모두 +Z 가 광축(ROS optical)인데 USD 카메라는 −Z 가 전방입니다.
      그대로 붙이면 뒤를 봅니다. X축 180° 회전이 필요합니다.

--- 2.3 ★ 눈으로 맞추지 마세요 — 픽셀로 검증합니다 ---

      광축에서 θ 만큼 떨어진 점의 화면 좌표
          u = (W/2) · ( 1 + tanθ / tan(FOV/2) )

    C920 (1280×720)                     D435i RGB (1280×720)
      가로 +10° →  800.0 px   −10° → 480.0     가로 +10° →  804.2 px
      가로 +20° →  970.2 px   −20° → 309.8     가로 +20° →  978.9 px
      가로 +30° → 1163.8 px   −30° → 116.2     가로 +30° → 1177.6 px
      세로 +10° →  519.9 px   −10° → 200.1     세로 +10° →  525.4 px
      세로 +15° →  603.0 px   −15° → 117.0     세로 +15° →  611.3 px

    씬에 검증용 마커 4개를 놓아 주세요 — 카메라 앞 1 m, 광축에서
    좌우 ±20°, 상하 ±15°. 위 픽셀에 찍히면 통과입니다.

    ★ **상하를 꼭 넣어 주세요.** −Z/+Z 를 잘못 잡으면 상하가 뒤집히는데,
      좌우 대칭 장면에서는 절대 안 드러납니다. 저희는 손목 롤 축을 X 로
      잘못 잡고도 한쪽 방향으로는 그럭저럭 돌아서 한참 못 찾았습니다.

  ✅ 통과 기준
      [ ] 마커 4개가 계산 픽셀 ±15 px 안에 찍힌다 (상하 포함)
      [ ] 50/55/60/65° 렌더 4장
      [ ] 정한 각도에서 광축이 닿는 바닥 지점이 위 표와 일치

  ✅ 통과 기준

 4. V-3  집기 → 넣기 전체 궤적이 존재하는가     ★★
================================================================================

  쓰레기통 위치를 정하기 위한 것입니다. **아직 안 만들었으니 지금이 기회입니다.**

--- 4.1 제약 (제가 전수 계산한 값, scripts/14_reach_map.py) ---

      툴을 아래로 향한 채 도달 가능한 최대 높이   **428 mm** (본체 좌표)
        아래 ±45° 까지 허용하면 483 mm · ±60° 면 541 mm

      ★ **본체 높이가 831 mm 입니다. 상판에 쓰레기통을 얹으면 못 닿습니다.**
        개구부는 z ≤ 400 mm 여야 합니다.

      z=400 mm 에서 툴을 아래로 향한 채 닿는 범위: 본체 x +2 ~ +627 mm

--- 4.2 부탁드리는 것 ---

    쓰레기통 개구부 후보를 2~3개 놓고, 바닥 격자의 각 점에서
    **집기 → 들어올리기 → 개구부 위 → 놓기** 경로가 충돌 없이 존재하는지
    확인해 주세요.

    후보 예 (본체 좌표, 개구부 중심)
        A  ( +250,   0, 350 )   앞면 상단
        B  ( +150, +250, 300 )  측면
        C  ( +300,   0, 250 )   앞면 낮게

    개구부는 ∅150 mm 이상을 권합니다. 크면 정렬 오차를 흡수해서 성공률이
    크게 오릅니다.

  ✅ 통과 기준
      [ ] 후보별로 "집어서 넣을 수 있는 바닥 영역" 넓이 (cm²)
      [ ] 가장 넓은 후보와 그 개구부 좌표
      [ ] 그 궤적의 대표 영상 또는 스냅샷 몇 장

 6. V-5  텔레옵 인간공학                        ★
================================================================================

  과소평가되는 항목입니다. **시연자가 힘들면 데이터가 나쁘고, 데이터가
  나쁘면 정책이 나쁩니다.** 실물에서 500개 모으다가 "자세가 불편하다"를
  깨달으면 다시 모아야 합니다.

  사용자가 VR 로 시뮬 물체를 20~30회 집는 동안 아래를 기록해 주세요.

      · 에피소드당 소요 시간
      · **클러치를 다시 잡은 횟수** (많으면 스케일이 안 맞는 것입니다)
      · 관절 리밋에 닿은 횟수와 어느 관절인지
      · 실패했다면 그 이유 (못 봄 / 못 닿음 / 놓침 / 넣다가 떨어뜨림)

  참고 — 현재 조종 스케일은 **0.861** 입니다 (팔 리치 0.5596 / 사람 팔 0.65).
  손을 100 mm 움직이면 팔 끝이 86.1 mm 움직입니다.

  ★★ **2026-09-03 갱신 — joint1 영점 이동은 취소. 대신 joint5 origin 이 [0 0 −π] 입니다.**
    첨부 URDF 가 그 판입니다. 09-02 자료를 갖고 계시면 버려 주세요.

        joint1   origin rpy  [0 0 0]      (원래대로)
        joint5   origin rpy  [0 0 −π]     ← 그리퍼를 motor5 에 180° 돌려 단 것을 모델
        홈       [0, -54.51, +84.45, +80.78, +4.90]°   j1 = 0 · 정면

    이유 — 카메라 위/아래는 j1 이 아니라 **j5** 가 정합니다 (기구 담당 71번 §1).
    그리퍼 조립체를 180° 돌려 달면 j5=0 에서 카메라가 위로 오고, 홈이 기계
    중립 근처가 됩니다. 관절값 규약은 안 바뀝니다.

    ★ 브릿지가 q 를 그대로 관절에 넣는다면 바꿀 것이 없습니다. USD 만 새
      URDF 로 다시 뽑으면 됩니다.

  ★ 그래도 남는 약점: 팔이 물리적으로 반 바퀴 돌아 있는 상태로 일합니다.
    카메라가 link5 의 +x 쪽에 달려 "카메라를 그리퍼 위로" 하려면 그럴 수밖에
    없기 때문입니다. 조종해 보시고 걸리적거리면 **카메라를 −x 로 옮기는**
    기구 변경을 조립 전에 요청하겠습니다.

  ✅ 통과 기준
      [ ] 20회 이상의 기록표
      [ ] 스케일 조정이 필요한가에 대한 의견
      [ ] joint1 리밋이 실제로 문제가 되는가

 7. 브릿지에서 바뀌는 것 — 그리퍼가 생겼습니다

      import gripper_map as gm                  # assets/arm_v2/gripper_map.py
      opening = 57.9 + (0.5 - 57.9) * clip(grasp, 0.0, 1.0)
      servo   = gm.servo_for_opening(opening)   # 유효 10~120°
      l, r    = gm.rocker_deg(servo)
      # URDF 관절값 (rad)
      gripper_joint  = radians(45.10 - l)
      rocker_r_joint = radians(r - 52.47)
      jaw_l_joint    = -gripper_joint
      jaw_r_joint    = -rocker_r_joint
