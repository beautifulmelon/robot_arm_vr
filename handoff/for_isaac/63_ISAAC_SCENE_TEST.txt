 0. 이번에 만들 것 — 한 장
--------------------------------------------------------------------------------
  사용자가 "VR 로 조종하면서 카메라 화면을 확인" 하는 것을 한 번 해보려 합니다.

      본체 + 팔 + 손        body_with_arm_nomimic.urdf → USD
      카메라 2대            C920(본체 정면) · D435i RGB(손목)
      바닥에 테스트 박스     70mm 큐브 1개
      VR 조종               지금 쓰는 UDP 브릿지 그대로

  ★ **카메라는 정면(0°) 그대로 둡니다.** 사용자 지시입니다.
    61번에서 60° 기울이자고 했지만, 이번엔 "일단 그대로" 로 갑니다.

  ★ 그래서 **바닥 박스는 본체 카메라에 안 보입니다.** 이것도 확인된 사항이고
    사용자가 "동시에 보이지 않아도 괜찮다" 고 했습니다. 자세한 건 §3.

 2. 카메라 2대
================================================================================

  파라미터는 62번에 계산해 둔 값 그대로입니다.

    본체 정면 — Logitech C920      프레임 body_camera_mount
        focal_length         24.0
        horizontal_aperture  33.8603
        vertical_aperture    19.0530
        → HFOV 70.40° · VFOV 43.30°
        해상도 1280×720 (16:9)
        ★ 기울기 없음. body +X(정면) 를 그대로 봅니다.

    손목 — RealSense D435i **RGB**   프레임 camera_mount
        focal_length         24.0
        horizontal_aperture  32.9895
        vertical_aperture    18.4255
        → HFOV 69.00° · VFOV 42.00°
        해상도 1280×720 (16:9)

  ★★ D435i 를 87° 로 넣지 마세요. 87° 는 depth 이고 **RGB 는 69°** 입니다.
     기존 문서(05번 323행)에 87° 로 적혀 있어 그대로 쓰면 가로 시야가
     실물보다 26% 넓어집니다. 62번 §3 참고.

  ★ USD 카메라는 −Z 가 전방인데 두 프레임 모두 **+Z 가 광축**(ROS optical)
    입니다. 그대로 붙이면 뒤를 봅니다. X축 180° 회전을 적용하세요.

  ★ 종횡비를 16:9 로 맞추세요. 위 aperture 는 16:9 전용입니다.


================================================================================
 3. 테스트 박스 — 위치를 계산해 뒀습니다
================================================================================

      크기      70 mm 정육면체
      위치      본체 좌표 ( x = 600, y = 0, z = 35 ) mm
                 (z=35 는 바닥에 놓인 70mm 큐브의 중심)
      질량      가볍게 (50~100 g). 잡히는지 보는 게 목적입니다
      마찰      기본값보다 조금 높게 (미끄러지면 파지 확인이 안 됩니다)

--- 3.1 왜 이 자리인가 ---

  ★ **IK 로 실제 도달을 확인했습니다** (손끝을 아래로 향한 자세, 300회 수렴):

        본체좌표          팔 base_link 기준        IK 오차
        (500, 0, 70)      [+0.186 0 -0.114]       36.1 mm  ❌ 못 닿음
        (550, 0, 70)      [+0.236 0 -0.114]        0.3 mm  ✅
        (600, 0, 70)      [+0.286 0 -0.114]        0.4 mm  ✅  ← 채택
        (650, 0, 70)      [+0.336 0 -0.114]        0.4 mm  ✅
        (700, 0, 70)      [+0.386 0 -0.114]        0.7 mm  ✅
        (600, ±150, 70)                            0.3~0.6 mm ✅

  · x=500 이하는 **너무 가까워서** 못 닿습니다 (팔 최소 리치 254mm).
  · x=600 은 어깨에서 322mm 로 리치(254~459mm) 한가운데라 여유가 있습니다.
  · 좌우로 ±150mm 옮겨도 닿으므로, 위치를 바꿔가며 시험하기 좋습니다.

  ※ 팔 어깨(base_link)는 본체 좌표 (314.4, 0, 184.5) mm 입니다.
  ※ 위 값은 hand_mount 기준입니다. 실제로는 손 길이만큼 더 나가므로
    박스 위 몇 cm 에서 손이 감싸는 형태가 됩니다.

--- 3.2 ★ 본체 카메라에는 안 보입니다 — 정상입니다 ---

  카메라가 정면(0°)이라 바닥 박스는 **광축에서 49° 아래**에 있습니다.
  수직 반각이 21.65° 이므로 시야 밖입니다.

      박스 (600, 0, 35) → C920 기준 수평 0.0° / 수직 +49.4°  → 시야 밖

  정면 카메라가 각 거리에서 보는 최저 높이는 이렇습니다.

        본체 앞 400mm → z 603mm 아래는 안 보임
        본체 앞 600mm → z 523mm
        본체 앞 1000mm → z 365mm
        본체 앞 1951mm → z   0mm   ← 바닥이 겨우 들어오는 거리

  → 이번 테스트에서 **박스는 손목 카메라(D435i)로만 보입니다.**
    사용자가 "동시에 보이지 않아도 괜찮다" 고 확인해 주셨습니다.
    데이터 수집 단계에서는 61번의 60° 기울기를 다시 논의합니다.


================================================================================
 4. 카메라 화면을 사용자가 어떻게 볼 것인가
================================================================================

  사용자는 헤드셋을 살짝 걸치고 **RustDesk 로 Isaac 화면**을 봅니다.
  그래서 Isaac GUI 안에 카메라 뷰포트가 떠 있으면 그대로 확인됩니다.

  부탁
    · Isaac 뷰포트를 2개 띄워서 C920 / D435i 를 각각 배정
    · 또는 메인 뷰포트 + 카메라 뷰포트 2개 (3분할)
    · 어느 쪽이 어느 카메라인지 화면에 라벨이 있으면 좋겠습니다

  ※ 브릿지는 GUI 모드로 띄웁니다 (사용자가 창을 직접 닫아 종료합니다).


================================================================================
 5. 사용자 확인 절차 — 눈이 아니라 숫자로
================================================================================

  사용자가 직접 카메라 시선을 검증하겠다고 했습니다. 아래를 화면에서
  확인할 수 있게 준비해 주시면 좋겠습니다.

--- 5.1 화각이 맞는가 (픽셀 위치) ---

      광축에서 수평 θ 만큼 떨어진 점의 화면 x 좌표
          u = (W/2) · ( 1 + tan θ / tan(HFOV/2) )

      C920, 1280 폭 기준
          +10° → 800 px      +20° → 970 px      +30° → 1164 px
      D435i RGB, 1280 폭 기준
          +10° → 804 px      +20° → 979 px      +30° → 1178 px

  검증용 마커를 씬에 놓아주시면 사용자가 바로 확인할 수 있습니다.
  예: C920 앞 1 m, 광축에서 좌우 20°·상하 15° 지점에 작은 구 4개.
      → 화면에서 970 / 310 px (좌우), 그리고 상하 대칭으로 찍히면 통과.

  ★ 상하도 꼭 넣어주세요. −Z/+Z 를 잘못 잡으면 **상하가 뒤집히는데**
    좌우 대칭 장면에서는 안 드러납니다.

--- 5.2 카메라가 어디를 보는가 (광축이 닿는 지점) ---

      정면(0°)이므로 광축은 **바닥과 만나지 않습니다.**
      대신 이렇게 확인합니다:

      · 화면 정중앙에 찍히는 것은 본체 앞 어느 거리든 **z = 774 mm** 높이입니다
      · 박스(z=35mm)를 화면에 넣으려면 카메라를 기울이거나 물체를 올려야 합니다

      ※ 나중에 60° 로 기울이면: 광축이 본체 앞 447 mm 바닥에 닿습니다.
        그때는 화면 정중앙이 그 지점이면 각도가 맞는 것입니다.

--- 5.3 손목 카메라가 손을 보는가 ---

      팔 자세를 4개 이상 바꿔가며 **매번** 손이 화면에 들어오는지 봅니다.
      한 자세에서 우연히 보이는 것과 항상 보는 것은 다릅니다.
      (57번 §3 에서 그렇게 하시겠다고 한 그대로입니다)

 6. 실행 순서
================================================================================

    1) body_with_arm_nomimic.urdf → USD 변환
    2) 브릿지의 USD 경로 교체 + BASE_LIFT 0
    3) 카메라 2대 추가 (§2), 뷰포트 배치 (§4)
    4) 박스 추가 (§3)
    5) 검증 마커 (§5.1) — 넣어주시면 사용자가 바로 확인
    6) 알려주시면 Mac 에서 붙이겠습니다:
         ./run.sh --motors jetson --profile isaac --jetson-host 100.93.186.122

  ★ 데이터 수집은 아직 하지 않습니다. 마찰이 안 들어갔고 카메라 각도도
    미확정입니다. 57번에서 합의한 "마찰 없이 한 에피소드도 모으지 않는다" 는
    그대로 유효합니다. **이번은 조종·시야 확인용입니다.**
