  작성일 : 2026-08-06
  보낸이 : VR 텔레옵 담당
  받는이 : Jetson / 모터 제어 담당
  대상 로봇 : 임시 테스트 팔 3-DOF (robot_arm_temp) + AmazingHand(선택)

 0. 한 장 요약
--------------------------------------------------------------------------------
  지금 VR 조종은 **전부 Mac 안에서만** 돌고 있습니다. 모터로 나가는 구간이
  통째로 비어 있습니다. 그 빈 자리가 젯슨이 들어갈 곳입니다.

      [현재]
        Quest 2 --WebXR/WSS--> Mac (서버+IK+시각화) --> (없음)

      [연동 후]
        Quest 2 --WebXR/WSS--> Mac (서버+IK) --UDP--> Jetson --CAN--> 모터
                                    ^                    |
                                    +----UDP 상태--------+

  젯슨이 구현할 것은 **딱 하나**입니다: UDP 로 관절각 3개를 받아서 CAN 으로
  모터에 넣고, 실제 관절각을 UDP 로 돌려주는 것. IK, WebXR, 좌표변환, 클러치
  전부 Mac 쪽에 이미 있고 젯슨은 몰라도 됩니다.

  ★ 다만 **안전 정지 판단은 반드시 젯슨에서** 해야 합니다 (§5).
    Wi-Fi 가 끊기면 Mac 은 아무것도 못 합니다. 모터 옆에 있는 쪽이 멈춰야 합니다.

 1. 지금 VR 조종이 어떻게 되고 있는가
================================================================================

 1-1. 전체 흐름
--------------------------------------------------------------------------------
    Quest 2 브라우저 (WebXR, 90 Hz)
      │   컨트롤러 gripSpace 포즈 + 버튼
      │   WebSocket over HTTPS (자체서명 인증서, 포트 4443)
      ▼
    Mac : xr_server.py       수신 서버 (FastAPI + uvicorn)
      ▼
    Mac : transforms.py      WebXR(RUB, y-up) → 로봇(z-up) 좌표변환
      │                      + 클러치 (grip 누른 동안만, 상대 변위)
      ▼
    Mac : 05_teleop_sim.py   목표 EE 포즈 생성 (30 Hz)
      ▼
    Mac : placo IK           관절각 q 계산 (0.03 ms)
      ▼
    Mac : 3D 시각화          VR 안 + 대시보드 (15 Hz 로 솎아서 전송)
      ▼
    ★ 여기서 끝. 모터로 안 나갑니다. ←──────── 젯슨이 들어갈 자리

 1-2. 각 구간 주기
--------------------------------------------------------------------------------
    Quest → Mac        90 Hz   (Quest 2 주사율)
    IK / 제어 루프     30 Hz   (control_dt = 1/30)
    Mac → 화면         15 Hz   (90Hz 를 그대로 밀면 헤드셋 렌더가 느려짐)
    Mac → 젯슨         30 Hz   ← 새로 만들 구간
    젯슨 → 모터        젯슨 쪽 결정 (§4-3 참고, 200~1000 Hz 권장)

 1-3. 조작 방식 (사람이 실제로 하는 것)
--------------------------------------------------------------------------------
    오른손 Grip 꾹     팔 추종 시작. 누른 순간의 손 위치를 기준으로 latch.
                       떼면 그 자리에 정지. 다시 잡으면 이어서.
                       (마우스를 들었다 놓는 것과 같은 개념 — '클러치')
    오른손 Trigger     손 쥐는 정도 0~1 (아날로그)
    오른손 A           홈 자세 복귀
    오른손 B           클러치 기준 리셋
    오른손 썸스틱 X    손목 롤

    ★ 절대 위치가 아니라 **상대 변위**입니다. 사람이 팔을 어디에 두고
      시작하든 상관없습니다. 젯슨 쪽은 이걸 몰라도 됩니다 — 이미 계산된
      관절각만 받으면 됩니다.

 1-4. 좌표변환 (참고용, 젯슨은 몰라도 됨)
--------------------------------------------------------------------------------
    R_WEBXR_TO_ROBOT = [[ 0,  0, -1],
                        [-1,  0,  0],
                        [ 0,  1,  0]]
    여기에 팔을 놓은 방향에 맞춘 yaw 보정(0/90/180/270)을 곱합니다.
    사람 손 변위 → 로봇 변위 스케일 = max_reach / 0.65 m
    임시 3-DOF 팔은 **0.390** 입니다 (사람이 10cm 움직이면 로봇은 3.9cm).

 2. 실물 팔 사양 (임시 테스트 팔, 3-DOF)
================================================================================

 2-1. 관절
--------------------------------------------------------------------------------
    URDF : assets/robot_arm_temp/robot_arm_temp.urdf
    구성 : base_link -j1- link1 -j2- link2 -j3- link5 (+ hand_mount)

    idx  관절     가동범위              effort     velocity
    ------------------------------------------------------------------
     0   joint1   -178.0° ~ +178.0°     27 N·m     3.77 rad/s (216°/s)
     1   joint2   -100.0° ~ +100.0°     27 N·m     3.77 rad/s (216°/s)
     2   joint3   -178.0° ~ +178.0°     27 N·m     3.77 rad/s (216°/s)

    ★ 배열 순서는 위 idx 그대로 고정입니다. UDP 패킷의 q[0],q[1],q[2] 가
      joint1,2,3 입니다. 절대 바꾸지 마세요.

    단위 : **라디안**. 도(degree) 아닙니다.
    기준 : **URDF 관절 좌표계**. 모터 엔코더 원시값 아닙니다.
           감속비 40:1 이므로 출력축(관절) 기준으로 환산해서 주고받습니다.

    모터 : DM-J4340P-2EC, 40:1, 정격 9 N·m / 피크 27 N·m, CAN

 2-2. ★ 이 팔은 손끝을 안팎으로 못 움직입니다 (고장 아님)
--------------------------------------------------------------------------------
    joint3 의 회전축과 hand_mount 오프셋이 같은 z 축 위에 있어서, joint3 은
    손목 롤만 바꾸고 위치에는 전혀 기여하지 않습니다.

        joint3 을 ±178° 전 범위로 돌려도 손끝 이동 = 0.000000 mm (실측)
        위치 자코비안 랭크 = 임의 자세 600개 전부 2 (3 이어야 정상)
        방향별 전달률 : 껍질 따라 95%  /  안팎으로 1%

    -> 손끝이 곡면 위에서만 움직입니다. 팬-틸트 포탑 + 손목 롤이라고
       생각하시면 정확합니다.
    -> 시운전 중 "안팎으로 밀었는데 안 움직인다"는 정상입니다.
       위치 자유도가 joint1, joint2 둘뿐입니다.
    -> 이 팔의 목적은 위치 추종 성능이 아니라 **파이프라인 검증**입니다.

 2-3. 손 (AmazingHand) — 선택
--------------------------------------------------------------------------------
    붙일 경우 **서보 8개**를 별도로 명령합니다. 관절은 12개지만 서보는 8개입니다.

    ★ 반드시 **서보각**으로 명령하세요. 관절각으로 매핑하면 안 됩니다.
      관절 리밋 사각형의 55% 는 실물에서 나올 수 없는 조합입니다.
      (관절 공간에서 보간하면 중간에서 최대 11.44° 어긋나는 것 실측 확인)

    Mac 쪽에서 이미 서보각으로 변환해서 보냅니다. 젯슨은 받은 8개를 그대로
    서보에 넣으면 됩니다.

        열림 SERVO_OPEN_DEG  = [-35, 35, -35, 35, -35, 35, -35, 35]
        닫힘 SERVO_CLOSE_DEG = [ 90,-90,  90,-90,  90,-90,  90,-90]

    ※ 손 서보는 팔과 **다른 버스**입니다 (메시 이름으로 보아 SCS0009 계열
      시리얼 버스로 추정). 실제 무엇인지 알려주세요 — §8-Q4.
    ※ 손을 안 붙이면 패킷의 grasp/servo 필드를 무시하시면 됩니다.

================================================================================
 4. 프로토콜 규격 (안 1 기준)
================================================================================

 4-1. 전송 방식
--------------------------------------------------------------------------------
    UDP. TCP 아닙니다.

    이유: 관절 지령은 **절대값**이라 한 패킷 빠져도 다음 패킷이 덮어씁니다.
          TCP 는 재전송 대기 중 뒤 패킷이 막혀서(head-of-line blocking)
          오히려 오래된 명령이 늦게 도착합니다. 로봇 제어에서는 손실보다
          지연이 위험합니다.

    포트  Mac → Jetson  UDP 5005   (지령)
          Jetson → Mac  UDP 5006   (상태)

    형식  JSON 한 줄 (UTF-8). 30 Hz 라 대역폭은 문제되지 않고, 디버깅이
          훨씬 쉽습니다. 나중에 필요하면 바이너리로 바꿉니다.

 4-2. 지령 패킷 (Mac → Jetson, 30 Hz)
--------------------------------------------------------------------------------
    {
      "seq":    12345,              // 단조증가. 되돌아가면 무시할 것
      "t":      1754438400.123,     // 송신 시각 (Unix epoch, 초, float)
      "q":      [0.9495, 1.4765, -0.0419],   // 목표 관절각 3개 (rad)
      "enable": true,               // false 면 모터 소자
      "grasp":  0.0,                // 손 쥠 0~1 (손 없으면 무시)
      "servo":  [-0.61, 0.61, -0.61, 0.61, -0.61, 0.61, -0.61, 0.61]
                                    // 손 서보각 8개 (rad). 손 없으면 무시
    }

    필드 설명
      seq     패킷 순서. 젯슨은 seq 가 이전보다 작거나 같으면 버립니다
              (UDP 는 순서가 뒤바뀔 수 있음).
      t       Mac 시계 기준. 클럭 동기가 안 맞을 수 있으니 **절대 시각 비교로
              쓰지 말고**, 젯슨의 수신 시각으로 워치독을 판단하세요.
              t 는 로그 대조용입니다.
      q       URDF 관절 좌표계, 라디안. 배열 순서 joint1,2,3 고정.
      enable  false → 즉시 소자. ★ 소자하면 팔이 중력으로 떨어집니다.
              시운전 때는 팔을 받치거나 낮은 자세에서 하세요.

 4-3. 상태 패킷 (Jetson → Mac, 30 Hz 이상)
--------------------------------------------------------------------------------
    {
      "seq":   12345,               // 마지막으로 처리한 지령의 seq
      "t":     1754438400.130,      // 젯슨 송신 시각
      "q":     [0.9481, 1.4702, -0.0418],   // 실제 관절각 (rad)
      "dq":    [0.01, -0.02, 0.00],         // 관절 속도 (rad/s), 없으면 0
      "tau":   [1.2, 4.8, 0.03],            // 토크 (N·m), 없으면 생략 가능
      "temp":  [38.0, 41.5, 36.0],          // 모터 온도 (°C), 없으면 생략 가능
      "err":   [0, 0, 0],                   // 모터별 에러코드, 0 = 정상
      "state": "RUN",               // "IDLE" | "RUN" | "TRIP"
      "trip":  null                 // TRIP 이면 사유 문자열
    }

    ★ q(실제값)는 반드시 보내주세요. Mac 쪽 안전계층이 "지령이 실제보다
      너무 앞서갔는지"를 이 값으로 판단합니다. 이게 없으면 모터가 막혔을 때
      오차가 계속 쌓이다가 장애물이 치워지는 순간 튑니다.

    ★ state 가 TRIP 이면 Mac 쪽은 조종을 멈추고 화면에 사유를 띄웁니다.
      TRIP 해제는 사람이 명시적으로 해야 합니다 (자동 복구 금지).

 4-4. 연결 절차
--------------------------------------------------------------------------------
    1) 젯슨 부팅 → UDP 5005 리스닝, state="IDLE", 모터 소자 상태
    2) Mac 이 enable=false 인 지령을 보내며 링크 확인 (상태 패킷 수신 확인)
    3) Mac 이 실제 q 를 읽어 IK 시작점을 거기에 맞춤   ← ★ 중요
    4) Mac 이 enable=true 전송 → 젯슨 여자, 소프트스타트 2초 시작
    5) 조종 시작

    ★ 3) 을 빠뜨리면 여자하는 순간 팔이 홈 자세로 최대 속도로 튑니다.
      시운전 사고의 가장 흔한 원인입니다.


================================================================================
 5. 안전 요구사항 (젯슨 쪽에서 반드시 구현)
================================================================================

  네트워크가 끊기면 Mac 은 아무것도 못 합니다. 아래는 전부 **젯슨에서**
  판단해야 합니다. Mac 쪽에도 같은 계층이 있지만 그건 보조입니다.

 5-1. 워치독 [필수]
--------------------------------------------------------------------------------
    마지막 지령 수신 후
      100 ms 초과 (3프레임)  → 현재 지령을 **유지**(freeze). 계속 보정만.
      500 ms 초과            → TRIP. 정지.

    ※ 수신 시각은 젯슨 자체 시계(monotonic)로 재세요. 패킷의 t 를 쓰면
      클럭 오차에 당합니다.

 5-2. 관절 한계 [필수]
--------------------------------------------------------------------------------
    §2-1 의 가동범위에서 **0.05 rad(2.9°) 안쪽**까지만 허용.
    하드 스톱에 부딪히지 않게 하는 마진입니다.

 5-3. 속도 제한 [필수]
--------------------------------------------------------------------------------
    한 스텝 이동량 = velocity_limit × dt 로 제한.

    ★ 시운전은 **velocity_scale = 0.1** 로 시작하세요.
      URDF 값 3.77 rad/s 의 10% = 0.377 rad/s (21.6°/s).
      관절별로 하나씩 확인한 뒤 0.3 → 그 이상으로 올립니다.

    ★★ 주의 — velocity_scale 은 속도만이 아니라 **사실상 토크 상한**입니다 ★★

      max_step = max_velocity × velocity_scale × dt
      max_lag  = max(max_step × 5, 0.05)      ← 아래 5-5 이격 제한
      → 지령-실제 오차가 max_lag 을 못 넘음
      → 임피던스 제어 토크 τ ≈ kp × 오차
      ∴ **낼 수 있는 최대 토크 ∝ velocity_scale**

          scale   max_lag   정지→출발 도약   kp=100 일 때 최대토크
          0.1     0.0628        3.6°              6.3 N·m
          0.3     0.1885       10.8°             18.9 N·m
          0.5     0.3142       18.0°             31.4 N·m

      → **팔이 안 움직이면 kp 가 아니라 velocity_scale 을 먼저 올려보세요.**
        마찰이 큰 팔은 0.1 에서 아예 안 움직입니다. 실기에서 kp 를 8→100 으로
        12배 올려도 증상이 그대로였고 velocity_scale 한 번에 해결됐습니다.

      → 반대로 올리면 **정지에서 출발할 때의 도약이 커집니다.** 오차가
        max_lag 까지 쌓였다가 한 번에 풀리기 때문입니다. 맞바꾸기입니다.

 5-4. 소프트 스타트 [필수]
--------------------------------------------------------------------------------
    여자 직후 **2초** 동안 속도 한계를 0 에서 선형으로 올립니다.
    전원 넣은 순간 실제 위치와 목표가 다르면 첫 명령에서 최대 속도로 튑니다.

 5-5. 지령-실제 이격 제한 [필수]
--------------------------------------------------------------------------------
    지령이 실제 관절각보다 max(한스텝×5, 0.05 rad) 이상 앞서가지 않게
    끌어당깁니다. 모터가 못 따라오는 상황에서 오차 누적을 막습니다.

 5-6. 물리 비상정지 [강력 권장]
--------------------------------------------------------------------------------

 6. 시운전 전에 반드시 맞춰야 할 것 — 관절 방향과 영점
================================================================================

  여기가 실물 연동에서 제일 자주 틀리는 곳입니다. URDF 의 관절 0 과 모터의
  엔코더 0 이 다르고, 회전 방향(+/-)도 다를 수 있습니다.

  아래 표를 **젯슨 쪽에서 채워서** 돌려주세요. Mac 은 URDF 좌표계로만
  이야기하고, 변환은 젯슨에서 합니다.

      관절     CAN ID   기어비   부호(+1/-1)   영점 오프셋(rad)   비고
      -------------------------------------------------------------------
      joint1   [    ]   40:1     [        ]    [            ]
      joint2   [    ]   40:1     [        ]    [            ]
      joint3   [    ]   40:1     [        ]    [            ]

      변환식:  q_motor = sign × (q_urdf) + offset
               q_urdf  = (q_motor - offset) / sign

  확인 절차 (관절 하나씩, 나머지는 소자 또는 받침):
    1) 팔을 육안으로 URDF 기본자세(전부 0)에 맞추고 그때의 엔코더값을 읽는다
       → 그 값이 offset
    2) q_urdf 를 +0.1 rad 만 명령한다
    3) URDF 의 axis 방향(오른손 법칙)과 같은 쪽으로 돌면 sign=+1, 반대면 -1

       URDF axis:  joint1 = (0,0,-1)   joint2 = (-1,0,0)   joint3 = (0,0,-1)

    4) ±0.2 rad 왕복시켜 부드럽게 도는지 확인

 8. 확인 부탁드릴 것
================================================================================

  Q1. 젯슨을 안 1(얇은 브리지)로 갈까요, 안 2(전부 실행)로 갈까요?
      안 2 라면 ARM64 에서 placo / pinocchio 설치가 되는지 먼저 확인
      부탁드립니다. 안 되면 안 1 이 강제됩니다.

  Q2. 네트워크 구성이 어떻게 되나요?
      - 젯슨과 Mac 이 같은 Wi-Fi 인가요, 유선으로 직결인가요?
      - 유선이 가능하면 유선을 권합니다 (지연·끊김 모두 유리)
      - 젯슨 IP 는 고정인가요? (Mac 쪽 IP 가 계속 바뀌어서 고생 중입니다)

  Q3. CAN 어댑터는 무엇이고 젯슨의 어디에 붙나요?
      (USB-CAN? 젯슨 내장 CAN 컨트롤러? 비트레이트는?)

  Q4. 손(AmazingHand)을 이번에 붙이나요?
      붙인다면 서보 버스가 무엇인가요? (SCS0009 시리얼로 추정 중)
      안 붙이면 팔 3축만 하고 손 필드는 무시하시면 됩니다.

  Q5. 팔을 어디에 어떻게 고정하나요?
      base_link 형상이 프레임 원점보다 **56.5 mm 아래로** 내려갑니다.
      테이블에 그냥 놓으면 파고듭니다. 받침을 대나요, 구멍이 있나요?
      시뮬레이션 바닥 높이를 여기에 맞춰야 합니다.

  Q6. 지령 주기 30 Hz 로 충분한가요?
      모터 쪽에서 더 높은 주기를 원하면 젯슨이 보간(interpolate)하는 쪽을
      권합니다. Mac→젯슨 구간을 무리해서 올리는 것보다 안전합니다.

  Q7. 상태 패킷에 토크/온도를 넣을 수 있나요?
      없어도 동작하지만 있으면 시운전 때 훨씬 안전합니다.
