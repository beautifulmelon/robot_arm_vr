 2. §7-다 큰 이동 연속 추종 — 됩니다
================================================================================

  조건: kp 100 / kd 2.0 / velocity_scale 0.3 / delta 0.3 rad (joint1)

 2-1. 복귀 이동은 거의 완벽했습니다
--------------------------------------------------------------------------------
      실제  0.3857 → 0.3822 → 0.3761 → 0.3693 → 0.3574 → 0.3464 → 0.3357
          → 0.3246 → 0.3128 → 0.2892 → 0.2571 → 0.2354 → 0.2220 → 0.2049
          → 0.1930 → 0.1808 → 0.1690 → 0.1614 → 0.1492 → 0.1419 → 0.1331
      오차  0.1885 에서 0.0023 까지 매끄럽게 감소, 목표 도달

  **끊김 없이 연속 단조 감소했습니다.** 정지 구간이 사라졌습니다.

 2-2. 전진 이동은 최초 이탈만 걸립니다
--------------------------------------------------------------------------------
      정지 상태에서 오차가 0.1885(이격 한계)까지 쌓임  … 약 2초
      → 한 번에 0.1308 → 0.3162 로 **0.185 rad 도약**
      → 그 뒤로는 연속 추종, 끝에서 0.4433 → 0.4311 로 **감쇠 오버슈트**
      τ 최대 0.81 N·m

  kd 2.0 이 오버슈트를 잡고 있습니다.

 2-3. ★ 결론과 대가
--------------------------------------------------------------------------------
  · **"한 번 풀리면 운동마찰은 작다" 가 맞습니다.** 큰 동작은 문제없습니다.
  · 남는 것은 **정지에서 출발할 때의 도약**이고, 그 크기는 **정확히 이격
    한계와 같습니다.**

        velocity_scale 0.1  →  max_lag 0.0628  →  도약 3.6°
        velocity_scale 0.3  →  max_lag 0.1885  →  도약 **10.8°**

  ★ 즉 **추종을 부드럽게 하려고 scale 을 올리면 도약이 커집니다.** 손끝 기준
    3.6 cm 입니다. 맞바꾸기입니다. 이유는 §3-1 을 봐주세요.

  ★ §2-4 의 학습 우려에 대해: **큰 동작 구간은 깨끗합니다.** 문제는 정밀
    조작과 정지-출발 지점이고, 그 구간을 §5 의 IK 잔차로 표시해두면 학습에서
    걸러낼 수 있습니다. 그쪽 제안이 정확히 맞는 처방입니다.

 3. ★ 발견 2건
================================================================================

 3-1. velocity_scale 은 속도 한계가 아니라 **토크 상한**입니다
--------------------------------------------------------------------------------
  SafetyLayer 안에서 이렇게 연결돼 있습니다.

      max_step = max_velocity × velocity_scale × dt
      max_lag  = max(max_step × 5, 0.05)          ← 이격 제한
      오차는 max_lag 을 못 넘음
      MIT 토크 ≈ kp × 오차
      ∴ **낼 수 있는 최대 토크 = kp × max_lag ∝ velocity_scale**

  실측이 정확히 이 그림이었습니다.

      velocity_scale 0.1 → max_lag 0.0628 → 정지 구간 2~3초, 툭툭 끊김
      velocity_scale 0.3 → max_lag 0.1885 → 연속 추종

  ★ **kp 는 병목이 아니었습니다.** 8 → 30 → 60 → 100 으로 12배를 올려도
    증상이 그대로였고, velocity_scale 한 번에 해결됐습니다. 저희가 kp 를
    쫓느라 시간을 썼습니다.

  ★ 그래서 11번 문서 §5-3 의 **"시운전은 velocity_scale 0.1 부터"** 는
    의도와 달리 **"토크 권한을 1/3 로 줄이고 시작하라"** 는 뜻이 됩니다.
    마찰이 큰 팔에서는 **아예 안 움직입니다.** 그러면 조작자는 (저희처럼)
    kp 를 계속 올리며 엉뚱한 변수를 쫓게 됩니다.

    → 지침에 한 줄 넣기를 제안합니다.
      "안 움직이면 kp 가 아니라 velocity_scale 을 먼저 올려볼 것.
       이격 제한이 토크 상한을 만든다."

  ※ 이건 **그쪽 §2-1 의 텔레옵 스케일(0.390)과는 다른 변수**입니다.
    "마찰을 텔레옵 스케일로 가리지 말자" 는 §2-1 판단에는 전적으로 동의합니다.
    여기서 말하는 건 SafetyLimits 의 velocity_scale 입니다.

 3-2. MotorBackend.write_positions(q) 에 속도 인자가 없습니다
--------------------------------------------------------------------------------
  MIT 모드 토크는 이렇습니다.

      τ = kp × (p_des − p) + kd × (v_des − v) + τ_ff

  인터페이스가 `write_positions(self, q)` 뿐이라, 구현체는 **v_des 를 알 수
  없어 0 을 보냅니다.** 저희도 그랬습니다. 그런데 지령은 실제로 움직이는 중이라:

      velocity_scale 0.3 → 지령 속도 1.131 rad/s
      kd 2.0 × (0 − 1.131) = **−2.26 N·m**

  이 팔의 브레이크어웨이가 0.5~0.8 N·m 입니다. **자기 움직임에 그보다 큰
  제동을 걸고 있었습니다.** 스틱슬립의 "풀렸다가 다시 멈춤" 패턴이 이걸로
  설명됩니다.

  저희 조치 (젯슨 쪽)
    · `CanBackend.write_positions(q, dq=None)` — dq 를 안 주면 **직전 지령과의
      차분으로 스스로 구해** v_des 에 싣습니다. 호출부는 안 바꿔도 됩니다.
    · 마찰 피드포워드 `τ_ff` 도 옵션으로 넣었습니다. 이동 중일 때만 적용하고
      정지 상태에서는 안 넣습니다 (안 그러면 슬금슬금 흐릅니다).
    · 아직 실기 재시험 전입니다. 결과는 다음 회신에 넣겠습니다.

  ★ 그쪽에 부탁: **`MotorBackend` 인터페이스에 속도를 옵션으로 넣어주세요.**

        def write_positions(self, q, dq=None) -> None: ...

    없어도 저희는 차분으로 우회할 수 있지만, **인터페이스가 이 함정을
    유도하고 있습니다.** MockBackend 는 v_des 를 안 쓰니 시뮬에서는 절대
    안 드러납니다. 저희가 실물에서 만나기 전까지 아무도 몰랐던 것처럼요.

 5. §7-나 IK 잔차 / 클러치 engaged 기록 — 넣겠습니다
================================================================================

  (A-1) 통합 기록에 넣을 수 있습니다. 젯슨이 이미 둘 다 갖고 있습니다.

      observation   실제 관절각 (CAN 피드백) / 카메라 2대
      action        받은 지령 q
      추가          **잔차 = 지령 − 실제**  ← 젯슨이 매 틱 계산 중인 값입니다
      추가          engaged                ← ★ 프로토콜에 없습니다

  ★ **engaged 필드를 추가해 주세요.** grasp/servo 처럼 없으면 빠지는 방식이면
    좋겠습니다. 젯슨은 클러치를 모르므로 Mac 이 알려주는 수밖에 없습니다.

        "engaged": true      // 사람이 grip 을 잡고 있는가

  ★ 잔차가 왜 중요한지 그쪽 설명이 정확합니다. §2-3 대로 **지금 스틱슬립이
    일어나는 구간이 정확히 잔차가 튀는 구간**입니다. 그 구간을 학습에서
    걸러내는 것이 §2-4 우려에 대한 실질적인 답입니다.

  ※ §3-나 데이터셋 이동 — Tailscale rsync 로 충분합니다. 젯슨에 Tailscale 이
    이미 돌고 있고(100.107.9.105), NVMe 225 GB 여유가 있어 며칠치는 젯슨에
    쌓아두고 옮겨도 됩니다.
