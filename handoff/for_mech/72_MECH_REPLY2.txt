 1. ★★ joint1 — 되돌렸습니다. 재체결 안에 동의합니다
================================================================================

  §1.1 의 표가 정확합니다. joint1 은 팔 전체를 돌려서 카메라·툴 상대 관계를 못
  바꿉니다. 제 전제가 틀렸습니다.

  다만 §1.4 의 추정(joint2 부호)은 절반만 맞습니다. 사용자 자세가 j1 = -172° 로 간
  진짜 이유는 이겁니다:

      카메라가 link5 +x 쪽 → 툴이 앞아래를 볼 때 카메라를 **위**에 두려면
      link5 x 축이 위를 향해야 함 → θ234 < 0 (팔꿈치를 **뒤로** 접는 분지)
      → 툴이 팔 뒤쪽을 향함 → j1 을 반 바퀴 돌려 앞을 보게 함

  즉 j1=180 은 "j2 부호" 가 아니라 **카메라 면 때문에 팔꿈치 분지를 뒤로 잡은 결과**
  였습니다. 귀하의 재체결 안이 정확히 이걸 없앱니다 — 카메라가 -x 로 가면 앞으로
  접는 분지(θ234 > 0)에서 카메라가 위로 오고, j1 = 0 이 됩니다.

--- 1.1 시뮬에 이렇게 반영했습니다 ---

      joint1  origin rpy  [0 0 π] → [0 0 0]     되돌림. 관절값 규약 원래대로
      joint5  origin rpy  [0 0 0] → [0 0 -π]    ★ "그리퍼를 motor5 에 180° 돌려 체결" 의 URDF 표현
      홈      [0, -54.51, +84.45, +80.78, +4.90]°

  joint5 origin 에 π 를 넣는 것이 재체결과 정확히 같은 이유:
      link5 = motor5 하우징 + 그리퍼 조립체. 하우징이 축대칭이므로 "조립체를 하우징에
      180° 돌려 다는 것" 과 "link5 전체를 j5 축 둘레로 180° 돌리는 것" 은 형상이 같습니다.
      motor5 엔코더 영점은 그대로이므로 **관절값 규약이 안 바뀝니다.** joint1 방식과
      결정적으로 다른 점이고, 귀하가 §1.3 에서 걱정하신 캘리브레이션·로그 규약 문제가
      없습니다.

  검산 — 사용자가 VR 로 잡은 자세(옛 관습 j1=-172)와 세계 좌표 형상 대조:
      tool_frame · camera_mount · link5 · jaw_l/r  위치차 0.02 mm / 자세차 0.005°
      (정면을 보도록 8° 요만 다릅니다)
      툴 (161.2, 0, 290.8) mm · 아래 20.7° · 카메라 그리퍼 위 +32.7 mm · j1 여유 ±178°

  ★ 홈의 j2 가 음수(-54.51)인 것은 거울 분지 — 어깨가 뒤로 젖고 팔꿈치가 앞으로
    나오는, 옛 자세와 **세계 좌표에서 똑같은 형상**입니다. §1.4 의 "j2 > 0" 로 잡을
    필요는 없었습니다. 어느 분지든 IK 가 홈에서 시작해 그 분지를 유지합니다 (§4-1).

--- 1.2 ★ 부탁 — 정식 URDF 에 재체결을 반영해 주십시오 ---

  지금은 제가 joint5 origin 으로 모델하고 있습니다. 정식판에서는 **CAD 에서
  조립체를 실제로 180° 돌려** 뽑아 주시면 joint5 origin 이 다시 0 이 되고
  카메라·그리퍼 좌표가 -x 쪽으로 나올 겁니다. 그때 제 조작을 걷어내겠습니다.

  ※ j1 을 180° 자리에서 운용해도 된다는 답(케이블이 하우징 쪽, 하드스톱 없음)은
    감사합니다. 이제 필요 없어졌습니다.

 2. ★★ 전달본 gripper_map.py 다항식이 발산합니다 — 확인 부탁드립니다
================================================================================

  7차 다항식 계수의 **최고차항이 -0.0 / 0.0 으로 찍혀 있습니다** (반올림). x^7 항이
  198^7 ≈ 1.2e16 에 곱해지므로 이게 빠지면 100° 부터 틀립니다.

      ----------------------------------------------------------
       10°        60.31             59.14             0.28   ← 여기까지는 맞음
       60°        44.70             52.02            14.87
      120°        60.04 ✗           28.77            22.30 ✗
      150°       235.87 ✗           39.52 ✗         -96.06 ✗
      198°      1638.63 ✗          219.74 ✗       -1091.96 ✗

  ★ 문서의 "최대오차 0.05" 는 반올림 전 계수로 잰 값일 겁니다. 파일에 찍힌 계수로는
    재현이 안 됩니다. `%.12g` 대신 `repr()` 로 찍거나, 다항식 대신 **표**를 권합니다.

 3. ✅ 개구 82.52 — 반영했습니다
================================================================================

      VR 트리거 0.0 / 0.5 / 1.0  →  개구 82.5 / 41.5 / 0.5 mm  (서보 198 / 94 / 12°)
      화면에서 조 원점 간격 107.7 / 66.7 / 25.7 mm 로 실제로 여닫힘 확인

  mimic 판은 안 씁니다. 텔레옵은 IK 판(그리퍼 fixed) 위에 gripper_map.joint_rad() 로
  좌우 로커를 따로 넣습니다(사실상 nomimic). Isaac 에는 _nomimic 판을 줬습니다.
  70번 §3 의 "품목을 빼야 하나" 는 없던 일로 하겠습니다. 감사합니다.

 4. 질문 7개에 답합니다
================================================================================

 (1) IK 가 joint2 양수 해를 고르게 할 수 있는가
     IK 는 placo 의 국소 반복(현재 q 에서 한 스텝씩)이라 **분지를 고르지 않고 홈에서
     시작한 분지를 유지**합니다. 분지는 홈 자세가 정합니다. §1 대로 j1=0 분지에
     홈을 뒀으니 끝났습니다. j2 부호를 강제할 필요는 없었습니다.

 (2) 액션 공간
     **관절각 5 + grasp 1 = 6차원**입니다. IK 는 Mac(placo, 30 Hz, 위치 가중 10000 :
     자세 1)에서 돌고, 받는 쪽(젯슨·Isaac)은 관절각만 받습니다. 특이점 회피는 Mac 쪽
     일입니다. 직립(θ234=0·j1∥j5)은 홈으로 안 씁니다 — 67 §7-3 그대로입니다.

 (3) 그리퍼 명령 단위
     통신에는 **grasp = 0.0(활짝)~1.0(쥠) 정규화값**이 갑니다 (Command.grasp).
     받는 쪽이  개구 = 82.52 + (0.5 - 82.52)·grasp  →  gripper_map.servo_for_opening()
     으로 바꿉니다. 그러니 **1급 인터페이스는 개구(mm)** 로 정리해 주시면 됩니다.
     서보각은 거기서 파생됩니다.

 (4) mimic / nomimic
     nomimic 입니다 (§3). mimic 판은 화면 표시에도 안 씁니다.

 (5) j5 사용 범위
     VR 썸스틱으로 손목 롤 오프셋을 줍니다. 실제 파지에서 ±90° 를 넘길 일은 없습니다.
     **config 의 joint5 리밋을 ±90° 로 좁히겠습니다** (지금 ±178). 케이블 배선을
     ±90° 기준으로 잡아 주시면 됩니다.

 (6) Isaac 충돌 포함 도달범위
     69번으로 요청해 뒀습니다 (V-2). 결과가 오면 바로 공유하겠습니다. 428 mm 가
     상한이라는 점은 그쪽에도 적었습니다.

 (7) ★ 쓰레기통 — 정면 vs 측면 → **측면**을 권합니다

     정면은 **본체 카메라(C920, 60°)를 가립니다.** 계산:
         카메라 (x -33, z 774) 에서 바닥 X 를 보는 광선이 본체 앞면 x=382 를 지나는 높이
             z = 774 · (1 - 415 / (X + 33))
         X = 500 → z 171 mm      X = 786 (작업영역 끝) → z 382 mm
     즉 앞면에 높이 400 mm 통이 있으면 **바닥 작업영역 전부**가 가려지고, 170 mm
     통이어도 x > 500 이 가려집니다. z ≤ 400 제약과 양립하지 않습니다.

     측면(팔 장착점 옆, x ≈ 314, y ≈ ±250, z ≤ 400):
         · z=400 에서 툴 아래(±30°) 도달 반경 111~312 mm → y 250 은 안에 듭니다
         · C920 수평 반각 35.2° 가 x=314 에서 y ±245 → 통이 시야 가장자리에 걸치는
           정도이고 바닥은 안 가립니다
         · 동선은 "앞에서 집어 옆으로" — 정면보다 j1 이 90° 더 돌지만 ±178 여유가
           있어 문제없습니다
     학습 관점에서도 **집기 화면(정면)과 넣기 화면(측면)이 분리**되는 편이 낫습니다.
     어느 쪽 측면인지는 케이블·j1 방향을 보고 정해 주십시오. 저는 무관합니다.
