 0. 결론 먼저
--------------------------------------------------------------------------------
  §0 에서 지적하신 랭크 문제는 **사실입니다. 저희 쪽에서 독립적으로 재현했습니다.**

      joint3 을 ±178° 전 범위로 돌렸을 때 hand_mount 위치 변화
          = 0.000000 mm   (측정 한계까지 정확히 0)

      위치 자코비안(3×3) 랭크, 임의 자세 300개
          = 300개 전부 랭크 2.  3번째 특이값 최댓값 0.000e+00

  지적하신 원인도 그대로입니다. joint3 축이 z 이고 hand_mount 오프셋이
  [0, 0, 0.18850348] 로 같은 축 위에 있어서, 축 위의 점은 아무리 돌려도
  제자리입니다. joint3 은 손목 롤(자세)만 바꿉니다.

  다만 **이건 URDF 버그가 아니라 조립 구성의 결과**입니다.
  "link3 자리에 link5" 라는 구성 자체가 그런 기구학을 갖습니다.
  URDF 는 그 구성을 정확히 옮긴 것뿐이라, URDF 만 고쳐서 해결되지 않습니다.
  실물 조립을 바꿔야 하는 문제입니다.

 2. 제안 구성이 왜 이건지
--------------------------------------------------------------------------------
  §1 에서 "제3관절 축을 피치로" 권해주셨습니다. 방향은 동의합니다.
  다만 축만 바꾸려면 브래킷을 90° 돌린 새 부품을 만들어야 합니다.

  **기존 부품만으로 같은 효과를 내는 방법이 있습니다.**
  link3 을 빼지 말고 두고, link4 자리에 link5 를 넣는 것입니다.

      요청 구성   base_link -j1- link1 -j2- link2 -j3- link5        (3-DOF)
      제안 구성   base_link -j1- link1 -j2- link2 -j3- link3 -j4- link5  (4-DOF)

  joint4 가 바로 §1 에서 말씀하신 그 피치 축(axis = 1 0 0)입니다.
  새 부품이 필요 없고, 전체 5-DOF 팔에서 link4 하나만 빼면 됩니다.

  세 가지를 실제로 합성해서 재봤습니다 (임의 자세 600개):

    구성                              위치랭크   리치(mm)      같은방향 거리폭
    --------------------------------------------------------------------------
    A 요청: link3자리 link5, 요        2      236.1~294.5      0.3 mm   껍질
    B 같은자리 축만 피치(1 0 0)        3       82.6~293.5     46.2 mm   부피
    C 제안: link4자리 link5            3      203.6~482.6    109.0 mm   부피

  C 가 작업공간도 가장 넓습니다. 리치가 A 의 294 mm 에서 483 mm 로 늘고,
  같은 방향 거리폭이 0.3 mm → 109 mm 가 됩니다.

  ※ B 도 유효합니다. 새 브래킷을 만드실 생각이면 B 로 가도 됩니다.
    말씀 주시면 B 형상 URDF 도 바로 뽑아 드립니다.


 3. 결정해 주셔야 하는 것
--------------------------------------------------------------------------------
  실물을 어떻게 조립할지가 정해져야 확정본을 드릴 수 있습니다.

      [ ] A 로 간다  — 3-DOF, 위치는 2-DOF. 손목 롤만 추가되는 셈.
                      텔레옵 위치 추종 테스트는 사실상 불가.
      [ ] C 로 간다  — 4-DOF, 기존 부품만. 새로 만들 것 없음.   ← 권장
      [ ] B 로 간다  — 3-DOF, 브래킷 신규 제작 필요.

  저희 프로젝트 원칙이 "시뮬레이션이 실물과 정확히 일치할 것" 이라
  실물 조립이 확정되기 전에는 임의로 축을 바꾸지 않았습니다.


 4. 요청 §6 체크리스트 대응
--------------------------------------------------------------------------------
  [x] 제3관절 축을 피치로
        -> 확인했고 제안(C) 드렸습니다. 하드웨어 결정 대기 중. §2 참고.
  [x] hand_mount 프레임 포함
        -> 이름/값 모두 요청하신 그대로입니다.
             <joint name="hand_mount_joint" type="fixed">
               <parent link="link5"/> <child link="hand_mount"/>
               <origin xyz="0 0 0.18850348" rpy="-1.570796327 0 0"/>
             </joint>
           --ee-frame 은 hand_mount 로 쓰시면 됩니다.
  [x] 관절 limit 을 실제 가동범위로
        -> 전부 실측 CAD 값입니다. ±180° 가정 안 하셔도 됩니다.
             joint1 ±178°   joint2 ±100°   joint3 ±178°   joint4 ±120°
           effort 27.0 N·m (피크), velocity 3.77 rad/s 도 들어있습니다.
  [x] 메시 경로와 scale
        -> §4 (a) 방식. meshes/ 를 각 폴더에 복사해 넣었습니다.
           팔 STL 은 전부 mm 단위 + scale="0.001 0.001 0.001" 입니다.
           손 STL 은 m 단위라 scale 이 없습니다. 섞여 있으니 통일하지 마세요.
  [x] URDF 만 먼저 보내도 된다
        -> 그래서 손 포함본까지 같이 넣었습니다. 팔만 필요하시면
           robot_arm_temp.urdf 만 쓰시면 됩니다.


 5. 검증 현황
--------------------------------------------------------------------------------
  두 구성 모두 아래를 통과했습니다.

    메시 복사본            원본과 바이트 단위 동일 (sha256)
    링크 정의              전체 5-DOF 팔 URDF 와 완전 동일
    트리 구조              단일 루트, 끊긴 참조 없음
    손 방향                +Z = (0, 0, +1) 손끝 위
    자기충돌               임시 구성이 만든 신규 충돌 없음
                           (A: 19683자세 / C: 531441자세 스윕, 볼록껍질 기준)

  링크 정의가 원본과 완전히 동일하다는 게 핵심입니다.
  이 임시본들은 값을 다시 계산한 게 아니라 **검증 끝난 전체 팔 URDF 에서
  발췌**한 것이라, 메시 배치·관성텐서·리밋이 이미 검증된 값 그대로입니다.

  자세한 수치는 01_KINEMATICS_REPORT.txt 를 봐 주세요.
