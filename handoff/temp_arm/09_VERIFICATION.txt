   수신측 수정 1건: 메시 서빙 경로가 assets/robot_arm/meshes 로 고정돼 있어
   임시 팔 폴더의 메시를 못 찾을 수 있었습니다. 지금 쓰는 URDF 옆의 meshes/
   를 따라가도록 고쳤습니다. (지금은 메시가 동일 복사본이라 우연히 됐지만,
   B 안처럼 새 부품이 들어오면 404 가 났을 것입니다.)

 5. 회신
--------------------------------------------------------------------------------
   §3 의 A/B/C 결정 → ★ A 로 갑니다. (요청 구성 그대로, 보내주신 확정본 사용)

   랭크 2 라는 점은 양쪽이 확인했고, 그걸 알고 A 를 선택합니다.
   이 임시 팔의 목적이 '위치 추종 성능'이 아니라 '파이프라인 검증'이기 때문입니다.
   Quest 입력 -> 좌표변환 -> 클러치 -> IK -> 관절지령 -> 시각화 -> 데이터기록
   경로는 랭크와 무관하게 전부 돌아갑니다.

   따라서:
     - B 안 URDF 는 필요 없습니다. 제작하지 마세요.
     - C(temp4) 도 지금은 쓰지 않습니다. 폴더는 보관만 해두겠습니다.
     - robot_arm_temp/ 를 그대로 씁니다. 추가로 주실 것 없습니다.

   저희 쪽 처리:
     config/arm_temp.json 을 A 로 등록했고 ./run.sh --temp 로 돌아갑니다.
     위치 랭크가 3 미만이면 시작 화면과 대시보드에 경고를 띄우도록 했습니다.
     (안팎으로 밀어도 안 움직이는 것을 고장으로 오해하지 않도록)

     방향별 전달률 실측 (홈에서 ±8cm 왕복, 클램프 포함):
         껍질 따라(접선)  95%    <- 정상
         안팎으로(반경)    1%    <- 구조적 한계

   추가로 확인 부탁드릴 것 없습니다. 문서 품질이 높아 재작업이 없었습니다.
   특히 아래 세 가지가 유용했습니다.
     - 랭크 문제를 URDF 버그가 아니라 조립 구성의 결과로 정확히 구분해주신 것
     - 볼록껍질 기준 자기충돌 판정 (AABB 오보 경고 포함)
     - 메시 단위가 섞여 있으니 통일하지 말라는 경고
