# 학습 작업 계획 — 큐브 옮기기 → 음료수 컵 처리

작성일 2026-08-06

---

## 최종 목표 (사용자 정의)

플라스틱 음료수 컵을 받아서:

1. **빨대가 있는지 찾는다**
2. 있으면 **빨대를 먼저 빼서 버린다**
3. 음료수를 **본체로 가져와 본체에 끼운다**
4. **뚜껑을 연다**
5. **음료수가 들어있다면 버린다**
6. 나머지를 **쓰레기통에 버린다**

먼저 **큐브 집어 옮기기**로 파이프라인을 검증한 뒤 위로 넘어간다.

---

## 카메라 (확정)

| 위치 | 용도 |
|---|---|
| **본체 후상방** (팔 뒤, 위쪽) | 전역 시야 — 컵·쓰레기통·거치대 위치 |
| **손목** | 근접 시야 — 파지 정렬, 빨대 유무, 컵 내부 확인 |

모방학습의 표준 구성이고, 젯슨에 `/dev/video0`, `/dev/video1` 이 이미 있다.

> 손목 카메라가 **조건 판단 두 개를 모두 담당**한다 — 빨대 유무, 내용물 유무.
> 후상방 카메라만으로는 컵 안이 안 보인다.

---

## ⚠️ 먼저 — 지금 실물 팔로는 큐브 옮기기가 안 된다

책상 높이에서 손끝이 닿는 영역을 실측했다 (임의 자세 20만 개, ±5mm 슬라이스).

| | z=30mm | z=80mm | z=150mm |
|---|---|---|---|
| **임시 팔 (지금 실물)** | 반경 236.5~237.6mm → **폭 1.1mm** | 폭 1.0mm | 폭 4.3mm |
| **전체 5-DOF 팔** | 반경 236.7~476.8mm → **폭 240mm** | 폭 240mm | 폭 251mm |

임시 팔은 책상 위에서 **반경 237mm 짜리 두께 1mm 원** 위에만 닿는다. 면이 아니다.

→ **큐브를 A 에서 집어 B 에 놓는 것이 불가능하다.** 같은 원 위의 두 점 사이로만
옮길 수 있다. 위치 랭크가 2 라서 생기는 구조적 한계이고 설정으로 못 고친다.

**결론: 학습은 전체 5-DOF 팔로 한다.** 임시 팔은 파이프라인 검증 전용
(입력→변환→클러치→IK→UDP→모터→기록) 이며 여기서 데이터를 모으지 않는다.

## 손이 컵을 잡을 수 있는가 — 실측

`grasp` 값에 따른 엄지↔나머지 손끝 간격:

| grasp | 간격 | |
|---|---|---|
| 0.0 (폄) | 156.0 mm | |
| 0.5 | 85.9 mm | ← 테이크아웃 컵(70~90mm) 이 여기 |
| 1.0 (쥠) | 55.1 mm | |

**컵 크기에 잘 맞는다.** 컵은 grasp ≈ 0.5~0.7 에서 잡힌다.

> ⚠️ 반대로 **작은 물체는 어렵다.** 완전히 쥐어도 손끝이 55mm 까지만 모인다.
> 30mm 큐브는 손끝으로 못 집는다.
> **큐브는 60~80mm 로 준비할 것.** 컵과 크기대가 비슷해 나중 작업으로 옮기기도 쉽다.
>
> ※ 이 값은 손끝(distal) 사이 거리다. 실제로는 손가락 중간 마디로도 닿으므로
> 실물에서 한 번 확인이 필요하다.

## 핵심 설계 판단 — 본체 거치대

사용자가 정한 **"음료수를 본체에 끼운다"** 가 이 작업의 성립 조건이다.

뚜껑을 여는 동작은 원래 **양손 작업**이다 (한 손으로 컵을 잡고 다른 손으로 뚜껑).
팔이 하나뿐이면 못 한다. 그런데 컵을 본체 거치대에 끼워두면 **거치대가 두 번째
손 역할**을 한다. 그 뒤로는 전부 한 손 작업이 된다.

→ **거치대 설계를 지금 시작해야 한다.** 기구 담당자에게 미리 요청할 것.
   요구사항은 [handoff/15_CUP_FIXTURE_REQUEST.txt](../handoff/15_CUP_FIXTURE_REQUEST.txt).

## 작업 분해

전체 과정을 하나의 정책으로 학습시키지 않는다. **길고, 여러 단계이고, 조건 분기가
있기 때문이다.** ACT 같은 정책은 10~30초짜리 단일 기술에 강하고 그 이상은 무너진다.

### 조작 기술 (각각 정책 하나)

| | 기술 | 시작 → 끝 | 비고 |
|---|---|---|---|
| S1 | 컵 집기 | 책상 위 컵 → 손에 쥠 | |
| S2 | 빨대 빼기 | 컵 고정 상태 → 빨대 손에 | 거치대에 끼운 뒤가 쉬움 |
| S3 | 거치대에 끼우기 | 손에 쥔 컵 → 거치대 | ★ 정밀 삽입. 가장 어려움 |
| S4 | 뚜껑 열기 | 거치대의 컵 → 뚜껑 손에 | 스냅식이면 젖히는 동작 |
| S5 | 거치대에서 빼기 | 거치대 → 손 | S3 의 역 |
| S6 | 기울여 붓기 | 컵을 쥔 채 → 내용물 배출 | 손목 롤 사용 |
| S7 | 버리기 | 쥔 물체 → 쓰레기통에 놓기 | 빨대·뚜껑·컵 공용 |

S7 을 공용으로 쓰면 정책 수가 7개로 줄어든다.

### 조건 판단 (정책 아님 — 인식)

| | 판단 | 방법 |
|---|---|---|
| P1 | 빨대가 있는가 | 손목 카메라 이미지 분류 |
| P2 | 내용물이 있는가 | 뚜껑 연 뒤 손목 카메라로 컵 안 확인 |

> **조건 분기를 정책 안에 넣지 말 것.** 정책은 "빨대를 뺀다"만 배우고, "빨 대가
> 있는지"는 별도 인식이 판단한다. 섞으면 두 상황의 시연이 한 정책 안에서
> 충돌해서 어정쩡한 행동이 나온다.

### 전체 순서 (상태 기계)

```
컵 감지
  └ S1 컵 집기
     └ S3 거치대에 끼우기
        └ P1 빨대 있나? ─예→ S2 빨대 빼기 → S7 버리기
        └ S4 뚜껑 열기 → S7 버리기(뚜껑)
           └ P2 내용물 있나? ─예→ S5 빼기 → S6 붓기
              └ S7 컵 버리기
```

## 단계별 계획

### 0단계 — 파이프라인 검증 (임시 팔, 지금)
데이터 수집 없음. Quest → IK → UDP → 젯슨 → 모터 → 기록까지 한 번 관통.
젯슨 팀의 AP isolation 확인이 선행돼야 한다.

### 1단계 — 큐브 옮기기 (5-DOF 팔)
- 큐브 60~80mm, 책상 위 고정 구역
- **50 에피소드**, `lerobot-record`
- ACT 학습 → `lerobot-rollout`
- **목적은 큐브가 아니라 record→train→rollout 루프 자체의 검증**
- 여기서 막히는 것들을 다 겪고 넘어간다 (카메라 동기, 액션 스케일, 리셋 절차)

### 2단계 — 기술 하나씩 (S3 부터)
가장 어려운 **S3 거치대 삽입** 을 먼저 한다. 여기가 안 되면 전체가 안 된다.
- 기술당 **50 에피소드** 목표
- 되는지 먼저 보고 안 되면 거치대 형상을 고친다 (깔때기형 유도면 등)

### 3단계 — 나머지 기술
S1, S2, S4, S5, S6, S7. 총 **350 에피소드 규모** (7 × 50).
에피소드당 20~30초면 순수 조작만 3시간, 리셋 포함 2~3일.

### 4단계 — 인식 두 개
P1, P2. 이미지 분류라 시연보다 훨씬 싸다. 각 200~500장이면 충분.

### 5단계 — 이어붙이기
상태 기계로 순서를 엮는다. 기술 사이 전이에서 자세가 안 맞는 문제가 나올 텐데,
그때 각 기술의 시작/끝 자세를 규격화한다.

## 정책 선택 — 두 갈래

| | ACT 기술별 (권장 시작) | VLA 통짜 |
|---|---|---|
| 구성 | 기술 7개 × 정책 7개 + 상태기계 | π0 / SmolVLA 하나 + 언어 지시 |
| 데이터 | 350 에피소드 | 더 적을 수 있음 (사전학습 덕) |
| 디버깅 | 어느 기술이 실패했는지 바로 보임 | 어렵다 |
| GPU | 가볍다 | π0(3B)는 무겁다. SmolVLA 는 소비자 GPU 대상 |
| 조건 분기 | 상태기계가 처리 | 언어로 처리 |

**1~3단계는 ACT 로 간다.** 실패 지점이 보이는 게 중요하다.
전체가 한 번 돌아간 뒤 VLA 를 얹을지 판단한다.

> LeRobot 은 ACT / Diffusion Policy / VQ-BeT / VLA 계열을 모두 지원한다.
> 집 리눅스 GPU 사양을 알려주면 어느 쪽이 가능한지 정리하겠다.

## 지금 바로 확인해야 할 것

1. **뚜껑이 어떤 방식인가** — 스냅식(젖혀서 뜯음) vs 나사식(돌림)
   손목 롤은 ±178° 라 나사식이면 한 번에 못 돌리고 다시 잡아야 한다.
   S4 의 난이도가 완전히 달라진다.
2. **컵 규격 하나로 고정** — 지름·높이·뚜껑 종류. 여러 종류를 섞으면 데이터가
   몇 배로 필요하다. 하나로 시작해서 나중에 늘린다.
3. **쓰레기통 위치를 고정** — 팔 작업공간(반경 237~477mm) 안에 있어야 한다.
4. **거치대 설계 착수** — 리드타임이 가장 길다.
5. **집 GPU 사양**
