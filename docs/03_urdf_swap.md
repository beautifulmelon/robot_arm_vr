# URDF 교체 가이드

실물 팔의 URDF를 넘겨받았을 때 하는 일. **명령 한 줄이면 끝난다.**

```bash
.venv/bin/python scripts/06_setup_urdf.py --urdf /path/to/my_arm.urdf
.venv/bin/python scripts/05_teleop_sim.py          # 바로 텔레옵
```

---

## 1. 왜 한 줄로 끝나는가

처음에는 관절 이름·한계·리치·EE 프레임이 스크립트마다 하드코딩돼 있었다.
URDF를 바꾸면 여러 파일을 손봐야 하고, 하나라도 빠뜨리면 로봇이 엉뚱하게 움직인다.

[`ArmConfig`](../src/rpo_teleop/arm_config.py)를 만들어 **URDF를 단일 진실 공급원**으로 삼았다.
`06_setup_urdf.py`가 URDF에서 아래를 전부 도출해 `config/arm.json`에 저장하고,
다른 스크립트는 그 파일만 읽는다.

| 값 | 도출 방법 |
|---|---|
| 관절 이름·순서 | placo `RobotWrapper.joint_names()` (구동 관절만) |
| 관절 한계 / 토크 / 속도 | URDF `<limit>` 파싱. `continuous`는 ±π |
| EE 프레임 | 이름 후보 자동 탐색 → 실패 시 말단 링크. `--ee-frame`으로 지정 가능 |
| 어깨 위치 | 첫 구동 관절 프레임의 FK 위치 |
| 작업 공간·리치 | 관절 범위 균등 샘플링 20,000회 실측 |
| **스케일 계수** | `최대리치 × 0.97 ÷ 사람리치(0.65 m)` |
| 홈 자세 | 0을 관절 한계로 클립 |

---

## 2. 넘겨주실 때 필요한 것

### 필수
- **`.urdf` 파일**

### 함께 있으면 좋은 것
- **메시 파일** (`.STL` / `.dae`) — 없어도 기구학은 정상 동작하고 3D 뷰에서 해당 링크만 안 보인다
- 메시 경로가 `package://...`면 → `--fix-mesh-paths` 옵션으로 자동 정리

```bash
.venv/bin/python scripts/06_setup_urdf.py --urdf my.urdf --fix-mesh-paths
```

### 미리 확인만 하고 싶을 때

```bash
.venv/bin/python scripts/06_setup_urdf.py --urdf my.urdf --list-frames
```
관절과 프레임 목록만 출력하고 끝난다. EE 프레임 이름을 고를 때 쓴다.

## 3. 자동으로 대응되는 것

| 바뀌어도 되는 것 | 비고 |
|---|---|
| **자유도** (5든 6이든 7이든) | 6-DOF 이상이면 자세까지 정확히 추종한다 |
| 관절 이름·순서 | |
| 관절 한계·토크·속도 | |
| 팔 길이 / 리치 | 스케일 계수가 자동으로 다시 잡힌다 |
| EE 프레임 이름 | 자동 탐색 또는 `--ee-frame` |
| 왼팔 / 오른팔 | |
| 그리퍼·손 포함 여부 | 손 관절은 별도 처리 (아래 §5) |

## 4. 손봐야 할 수도 있는 것

**base_link 좌표계 관례.** 현재 코드는 `base_link`가 ROS **FLU**(x=앞, y=왼쪽, z=위)라고
가정한다. 이 가정은 [`transforms.py`](../src/rpo_teleop/transforms.py)의 `R_WEBXR_TO_ROBOT`
하나에만 들어있다.

URDF가 다른 관례(예: z가 앞)를 쓰면 손을 앞으로 밀었을 때 팔이 위로 가는 식으로 어긋난다.
`05_teleop_sim.py`를 돌려 **손을 앞으로 밀었을 때 팔도 앞으로 가는지** 한 번만 확인하면 된다.
어긋나면 `R_WEBXR_TO_ROBOT`만 고치면 되고, [테스트 6개](../tests/test_transforms.py)가
방향 감각을 못박고 있으므로 그 기대값도 함께 바꾼다.

**팔 장착 자세.** 거치대에 팔을 기울여 붙이면 작업 공간이 통째로 회전한다.
URDF에 마운트 각도가 반영돼 있으면 자동 처리되고, 아니면 `base_link` 위에 고정 관절을
하나 얹어 두는 편이 깔끔하다.

## 5. Amazing Hand가 URDF에 포함된 경우

손 관절까지 URDF에 들어있으면 `joint_names`에 8개가 더 잡혀서 **IK가 손가락으로 위치를
맞추려 든다.** 그건 원하는 동작이 아니다.

두 가지 방법:

1. **팔 URDF와 손 URDF를 분리** (권장) — 팔은 IK, 손은 별도 지령
2. 합친 URDF를 쓸 거면 `06_setup_urdf.py`에 손 관절 제외 옵션이 필요하다 (아직 미구현)

현재 `assets/rpo_arm/urdf/rpo_arm_right.urdf`에는 `hand_mount_link` 프레임만 있고
손 관절은 없다. 커넥터 실측 치수가 나오면 이 프레임 위치만 조정하면 된다.

---

## 6. 출력 읽는 법

```
IK 검증 (position soft 10000 : orientation soft 1, iters=5)
  ① 솔버 품질  — 목표를 FK 로 생성(반드시 도달 가능)
     성공 200/200  위치 0.000 mm  자세 0.00°  0.028 ms/call → 36357 Hz
  ② 자유도 충분성 — 작업공간 내 임의 위치 + 임의 자세 (충분히 수렴, iters=100)
     위치 20.1 mm  자세 85.2°
```

- **①이 실제 텔레옵 성능에 가깝다.** 매 프레임 목표가 조금씩만 움직이기 때문.
  여기서 위치오차가 크면 진짜 문제다.
- **②는 자유도가 충분한지 보는 지표.** 5-DOF 팔은 자세오차가 크게 뜨는 게 정상이다.
  6-DOF 이상이면 여기서도 작게 나와야 한다.

②의 위치오차는 반복 횟수에 따라 크게 변한다(실측 180 → 20 mm). 랜덤 자세에서 랜덤 목표로
점프시키는 최악 조건이라 수렴 전이가 섞이기 때문이며, **자세오차만 진짜 한계**다
(94° → 85°로 거의 안 줄어든다).
