## 2. 컨트롤러 프로파일

| 입력원 | `profiles[0]` | buttons | axes |
|---|---|---|---|
| Touch 컨트롤러 | `oculus-touch-v3` | **7** | **4** |
| 손 트래킹 | `oculus-hand` | **10** | **0** |

> ⚠️ Quest는 손 트래킹 중에도 `oculus-hand` 소스에 **합성 gamepad**를 붙여 보낸다.
> 입력소스를 `src.hand` 유무로 분리하지 않으면 같은 `handedness` 슬롯에서 서로 덮어쓴다.
> ([web/index.html](../web/index.html)에서 `payload.right`(컨트롤러) / `payload.handPose.right`(손) 로 분리 완료)

### 입력원은 배타적 (2차 측정 4,536 프레임으로 확정)

```
오른손: 컨트롤러만 1743 | 손만 1400 | 동시 0 | 전환중 1393
payload.right    → oculus-touch-v3 만
handPose.right   → oculus-hand 만
```

Quest는 컨트롤러를 내려놓으면 손으로, 들면 컨트롤러로 **자동 전환**하며 동시에 보내지 않는다.
→ 텔레옵 로직에서 우선순위 분기가 불필요: "컨트롤러 있으면 컨트롤러, 없으면 손".

## 5. gripSpace vs targetRaySpace

**컨트롤러 단독 프레임 (n=4,210): 자세차 48.15°, std 0.00°** — 완전히 고정된 오프셋.
위치차 40.7 mm ± 14.8.

(손 트래킹 소스가 섞인 프레임은 136.6° ± 13.8 로 튀는데, 이는 위 3절의 입력소스 충돌 때문이었고 수정 완료.)

### 결론: **`gripSpace`를 EE 목표로 쓴다**
- `targetRaySpace`는 컨트롤러에서 **앞아래로 48° 기울어진 포인팅 레이** 방향
- `gripSpace`는 "손으로 도구를 쥔" 기준 → 로봇 엔드이펙터 자세에 직관적으로 대응
- stock teleop은 `targetRaySpace`를 쓰고 있어 손목이 부자연스럽게 꺾임

## 6. 손 트래킹

| 항목 | 실측 |
|---|---|
| 감지 | ✅ 양손 (right 2,347 / left 2,209 프레임) |
| 전송 관절 | 6개 요약 — `wrist`, `thumb-tip`, `index-finger-tip`, `middle-finger-tip`, `ring-finger-tip`, `pinky-finger-tip` |
| 전체 관절 | 25개 (`handsFull = true` 로 전환 가능) |
| 엄지-검지 핀치 거리 | **3 ~ 141 mm** |
| 손가락 끝 radius | 5.4 ~ 6.6 mm |

→ 핀치 거리 3 mm까지 내려가므로 **Amazing Hand 쥐는 정도에 그대로 매핑 가능**.
→ 컨트롤러를 쥔 채로도 손 트래킹이 동시에 올라온다 (배타적이지 않음).

## 7. 확정 매핑안 (RPO 팔 5-DOF + Amazing Hand 8-DOF)

| 물리 입력 | 신호 | 용도 |
|---|---|---|
| 오른손 **grip** (`buttons[1]`) | `move` | **clutch** — 누르는 동안만 팔 추종. 뗐다 다시 잡으면 재기준(re-anchor) |
| 오른손 **gripSpace pose** | 6-DOF | 팔 EE 목표 (위치 + 자세) |
| 오른손 **trigger** (`buttons[0]`) | 0.0~1.0 | **Amazing Hand 쥐는 정도** (연속) |
| 오른손 **A** (`buttons[4]`) | on/off | 손 프리셋 — 펴기 |
| 오른손 **B** (`buttons[5]`) | on/off | 손 프리셋 — 핀치 |
| 오른손 **썸스틱 X** (`axes[2]`) | -1~+1 | 손목 롤 (`elbow_yaw`) — roboparty가 0으로 죽여둔 축을 되살림 |
| 오른손 **썸스틱 Y** (`axes[3]`) | -1~+1 | EE 스케일 조절 |
| 왼손 **trigger** | on/off | `lerobot-record` 에피소드 **시작/다음** |
| 왼손 **X** (`buttons[4]`) | on/off | 에피소드 **재녹화** |
| 왼손 **Y** (`buttons[5]`) | on/off | 녹화 **종료** |
| 왼손 **grip** | on/off | **비상 정지** (명령 송신 중단) |
| 오른손 **손 트래킹** | 25관절 | (2단계) Amazing Hand 손가락별 정밀 제어 |

> 왼손 버튼을 녹화 제어에 쓰면 헤드셋을 쓴 채로 데이터 수집을 끝까지 진행할 수 있다.
> LeRobot 기본 녹화 키(`→`/`n`, `←`/`r`, `Esc`/`q`)를 키보드 없이 대체.

## 8. 남은 이슈

1. **`Pose jump detected`** — `teleop` 패키지가 `move=False` 동안 `__previous_received_pose`를
   갱신하지 않아 grip을 잡는 순간 낡은 pose와 비교해 1프레임을 버린다.
   → 자체 pose 처리 경로를 쓰면 우회됨 (`teleop`은 HTTPS/WebSocket 전송에만 사용).
2. **네트워크 안정성** — 7초 무데이터 구간 2회, 재연결 1회 관측. 핫스팟 환경 특성일 수 있음.
   실제 데이터 수집 시에는 유선 공유기 권장.
3. **`buttons[6]` 썸레스트** — `value`는 항상 0, `touched`만 변함. 현재 `rawButtons`는 `value`만
   기록하므로 쓰려면 `touched`를 별도 전송해야 함.
