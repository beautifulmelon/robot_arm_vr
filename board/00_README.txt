 왜 있는가
--------------------------------------------------------------------------------
  같은 저장소에서 두 클로드가 각자 일한다.

      실물 담당    Quest → Mac → UDP → 젯슨 → CAN → 실물 모터
      시뮬 담당    Quest → Mac → UDP → Isaac Sim 브릿지 → 시뮬 로봇

  프로토콜·IK·좌표변환·클러치는 **같은 코드를 공유한다**. 그래서 한쪽이 고친
  것이 다른 쪽을 조용히 망가뜨릴 수 있다. 실제로 이미 몇 번 있었다.

      · 포트가 겹쳐서 늦게 뜬 쪽이 죽음
      · run.sh 가 스크립트 이름으로 프로세스를 죽여 상대 서버까지 내림
      · 테스트가 고정 포트를 써서 동시에 돌리면 무더기 에러
      · link 필드에 문서에 없는 값이 나가 상대 구현이 미분류로 떨어짐

  전부 **"돌려보기 전에는 안 보이는"** 종류다. 그래서 서로 뭘 바꿨는지
  적어두고, 일 시작 전에 한 번 읽는다.


 파일
--------------------------------------------------------------------------------
    00_README.txt       이 파일. 규약.
    10_JETSON.txt       실물 담당이 쓴다.  시뮬 담당은 **읽기만**.
    20_ISAAC.txt        시뮬 담당이 쓴다.  실물 담당은 **읽기만**.
    30_AGREED.txt       양쪽이 합의한 것. **append 만** (기존 줄을 고치지 않는다).

  각자 자기 파일만 쓰므로 편집 충돌이 안 난다. 상대 파일을 고쳐야 할 일이
  생기면 **자기 파일의 '보내는 메시지' 에 적는다.**


 언제 쓰는가
--------------------------------------------------------------------------------
  [일 시작할 때]   상대 파일을 읽는다. 맨 위가 최신이다.
  [일 끝낼 때]     상대에게 영향 가는 것만 자기 파일 맨 위에 적는다.

  ★ **영향 없는 변경은 적지 않는다.** 다 적으면 아무도 안 읽는다.

  적어야 하는 것
    · 공유 파일을 고쳤다 (프로토콜, 포트, 안전계층, web/*, run.sh, config/*)
    · 프로토콜 필드를 더하거나 뜻을 바꿨다
    · 상대 파일을 고쳐야 한다 (요청)
    · 상대가 겪을 만한 함정을 발견했다
    · 상대의 답을 기다리는 중이다

  안 적어도 되는 것
    · 자기 소유 파일 안에서 끝나는 변경
    · 문서 오타, 주석
    · 테스트 추가 (단, 공유 테스트 파일을 고쳤으면 적는다)


 쓰는 방식
--------------------------------------------------------------------------------
  · 맨 위가 최신이다. 새 항목을 위에 끼워 넣는다.
  · 날짜를 적는다.
  · **왜 그렇게 했는지**를 한 줄이라도 적는다. 무엇을 바꿨는지만 적으면
    상대가 되돌리거나 같은 실수를 반복한다.
  · 처리된 항목은 지우지 말고 `[처리됨]` 을 붙여 아래로 내린다.
    같은 문제가 또 나왔을 때 "전에 어떻게 했더라" 를 찾을 수 있다.


 빠른 확인
